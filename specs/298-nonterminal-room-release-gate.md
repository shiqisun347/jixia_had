# Spec 298 — 非终态房间发布门禁

- 版本：v2.0
- 状态：本地实现完成，待受保护发布
- 日期：2026-10-13
- 依据：线上只读审计发现预检只统计非终态比赛，未阻断独立的 WAITING/PAUSED 房间。

## 问题

房间可以在比赛记录之外保持 `WAITING` 或 `PAUSED`。若发布预检只检查非终态比赛为零，
仍可能在有房间连接或候场状态时重启 Core/Web，造成房间状态和连接租约丢失。

## 范围与验收

- `preflight_v2_1.sh` 查询并输出非终态房间总数及按状态计数。
- 非终态房间不为零时 fail-closed，输出明确的 `do not deploy` 原因；不修改房间状态。
- 保持现有非终态比赛、终态时间戳、租约、迁移、健康和资源门禁不变。
- QA 覆盖脚本包含房间门禁字段和只读性质；另以受控 JSON 替代初始数据库查询，真实执行
  shell `check_database` 和后续 Python 校验，验证零房间放行、有房间而零比赛仍阻断、
  字段缺失或类型错误拒绝放行；不读取或输出凭据。

## 本地完成证据（2026-10-13）

- `test_release_state.py` `16 passed`，包括六项真实预检行为回归；整个 QA 工具集
  `36 passed`，Ruff、Pyright 与 `git diff --check` 通过。
- 行为测试只替代初始查询，不连接数据库；迁移、房间、比赛和租约校验继续执行真实代码。
  未修改生产状态或执行发布。

## 回滚边界

仅移除新增房间计数查询、门禁和测试，保留其他发布检查；不写数据库、不重启服务、不改变
比赛状态机。移除后必须人工确认独立房间已排空，不能只凭比赛计数进入发布窗口。
