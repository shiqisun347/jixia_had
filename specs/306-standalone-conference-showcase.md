## 2. 展示页

视觉以现有辩论大屏为准：浅蓝白背景、深色正文、品牌顶栏、正方红色与反方蓝色、
左右各四席、中央信息主舞台及少量青绿强调。保持品牌，不改成另一套活动模板。

- 页面默认铺满视口；用户点击后进入浏览器全屏，Esc 正常退出。
  浏览器拒绝全屏时仍可正常铺满页面，不伪称浏览器允许自动进入全屏。
- 展示端不出现后台表单、导航栏、比赛控制、麦克风、发言倒计时或实时比赛状态。
- 后台发布后，已打开的展示端两秒内更新，无需刷新或重新输入网址。
- 主阶段严格为三个：观众投票、评委点评、结果公布；后台控制当前阶段，
  展示端跟随服务端已发布阶段，无需观众或大屏操作者自行切页。
  结果公布内可切换“观众票选排名”和“评委获胜方/最佳辩手”两个画面，
  全部使用同一个展示网址，不增加独立阶段或其他页面。
- 观众投票阶段的大屏显示投票说明与有效票数，不提前公开胜方/排名；手机投票模式
  提供匿名表单。评委点评阶段显示已发布点评，奖项结果留待结果公布；结果阶段
  按后台选择显示观众排名或评委奖项。
- 观众结果：胜方票数/样本量、前三领奖台及全部八位辩手的有序名单。
  同分使用稳定且明确的排序，不暗示真实并列已被决胜。
- 评委颁奖：获胜方、最佳辩手和评委文字；无结果时给出明确空态，不编造姓名和分数。
- 姓名、主张与长点评采用受控排版/分页，不让动态文字撑高页面或遮盖八席。
  只用 transform/opacity 过渡并尊重 prefers-reduced-motion。
- 无连接时保留最后已发布画面并提示连接状态；恢复后读取最新版本，旧响应不能覆盖新版本。

## 3. 控制台与数据

- 编辑会议标题、辩题、正反主张与八席名单/席位类型；不自动获取原平台数据。
- 编辑评委点评、胜方、最佳辩手，查看观众统计；最佳辩手只能选本场八席。
- 草稿编辑与正式发布分开；控制台有当前公开画面、小预览和中文阶段切换按钮。
  未发布的草稿不会从公开接口或展示页泄露。
- 可以发布、撤回展示和重新切换阶段，修改后显示服务端保存结果。
  两个控制窗口同时编辑时按版本冲突提示，不静默覆盖。
- 观众结果由有效匿名投票汇总，不允许后台覆盖原票；
  另行手工录入的外部统计必须标注来源，不混同为本站实时投票。
- 单站点轻量单体：静态 HTML/CSS/JavaScript，独立 Python Web 服务，SQLite 持久化。
  用独立虚拟环境和锁定依赖，不修改或共用原系统的可写虚拟环境。
- 公共状态返回只读已发布字段及递增 revision；请求/文本/列表有大小上限，
  同步使用有超时、无并发堆积的短轮询，不新增 Redis、消息队列或媒体服务。
- 独立服务限制 CPU/内存/并发和日志体量；只监听回环地址，由 1Panel OpenResty 转发。
  限额经独立站点测试后固定，不占用原平台的模型/媒体资源。
- 控制台与写接口统一使用独立管理员认证，口令不放 URL/前端包/源码/日志；
  会话使用 host-only、Secure、HttpOnly、SameSite Cookie，并校验写请求 Origin。
  不复用原平台账户、Cookie 或登录会话。

## 4. 匿名观众投票

- 手机投票模式无需注册、登录或加入原平台房间；选择胜方并排列完整八席。
- 排名操作提供上下移动或位置交换，后端独立校验八个固定 ID 全集且无重复。
- 只有后台开启当前轮投票才接受新票；关闭后拒绝提交，提交成功和重复提交有明确提示。
- 使用本站浏览器匿名标识与轮次唯一约束，配合有界频率限制、提交幂等，
  刷新、返回或网络重试不能重复记票。不使用 IP 作为唯一票权，避免现场共用 Wi-Fi 互相阻断。
- 明确防重范围为同一浏览器/轮次，不能宣称无需身份验证即可保证现实中每人一票。
- 不因无票自动产生获胜方或最佳辩手；汇总结果由服务器权威计算。
