## 2. 已定位的原因与证据边界

### 2.1 当前 Prompt 过度压缩且同质化

已发布 V12 的总结任务要求“三个短自然段、每段一句、每句最多60字、总共最多180字”，又在预算段重复180字上限，并叠加绝对上限、TARGET_CHAR_COUNT、保守写作字速、预留秒数等多重取小。不同长度的总结阶段仍被压到同一小规模，只容纳单项收益/代价，难以重建真实交锋。

既有内容对照中，四个总结样本新模板平均113.25字，旧模板平均523字；独立音频样本中12个总结的完整PCM时长中位约25.91秒。它们说明生成被主动压短，不能归因为核心只提供很短发言窗口，也不能用“60个样本自然结束”证明总结质量。

FREE 任务统一使用“先复述观察/问题→固定推断分支或一项理由→最多两句、短窗一句”，并禁止类比。这些共同要求压过 Agent 表达偏好，使多数发言都像同一种逻辑质疑。不是已有证据所支持的接入丢失 Prompt 问题。

当前可编辑正式范围为6套有启用Agent的规则、85个实例、670个阶段/用途槽位。本次预期只更新其中110个总结 SPEECH＋85个 FREE SPEECH，共195槽；其余475槽，包括全部 DECISION 和其他固定发言保持字节不变。实施时以正常配置枚举和精确 `(rule_id, agent_profile_id, stage_id, purpose)` 复核；范围漂移先停止对应写入，不按名字或音色猜测关联。

### 2.2 展示问题有直接实现原因

- 席位卡片的 `hidePortrait={thinking}` 及中心思考状态的 Bot 图标导致头像替换；小于等于700px的 CSS 还隐藏席位头像。
- 中央卡片的透明背景覆盖，以及仅48px的倒计时，削弱主持与倒计时的层次。大屏席位的白色背景覆盖了已有浅红/浅蓝底色。
- “查看赛后记录”有结束舞台、大厅房间卡片、已结束房间页三个可见入口。共享 `room-entry.ts` 同时控制自动导航，不能通过改该解析器粗略替换全部行为。

展示站根地址已只读 HTTPS 核对为200，标题“稷下 · 现场争鸣”；这仅证明入口可达，不代表本轮完成了其投票/现场音响验收。

## 3. 结辩与自由辩论 Prompt

### 3.1 总结回到真实交锋与比较

总结应回答“本场究竟争什么、哪些理由经交锋仍成立、为何本方在同一判准下更值得选择”，而不是重新做一次短开场。

- 从实际历史识别主要争点，准确重建对方最强合理主张，回应其已提出的关键反驳。根据内容选择展开几个重点，不强制三段三句，也不要求逐轮点名复述。
- 交代本方承担的真实代价、适用条件与仍待证之处，再比较双方举证完成度及重要后果。不把未回应当承认，不虚构对方已认输、数据、案例或已证收益。
- 允许清楚、有感染力的收束：具体处境、价值判断、恰当类比或节奏变化服务于论证，避免只喊“覆盖更广、收益明确、方案最优”。
- 删除一律180字、每句60字、限定主语、只能一项收益/代价等规则。根据原权威窗口和真实内容规划篇幅，TARGET_CHAR_COUNT 作为原有估算输入，而非叠加多轮保守压缩的理由。不强迫填满时间，不在文本生成后机械裁字。

### 3.2 FREE 按交锋需要自然变化

保留所有 Agent 的专业能力与稳定身份差异；每次由真实历史选择最有推进价值的表达方式，不轮换随机人格、不新增运行时随机规则。

可采用直接应答、具体例证、反例及边界、简短情景、可回答的追问、有限让步后的反击、因果解释、价值比较或简洁陈述。无需每次先复述、每次质疑对方逻辑、每次两句或套同一开头。类比须解释相关性，假设情景须明确是假设，情绪和修辞不替代证明。

长度随争点、上一轮未答问题和实际可用窗口自然变化：能一句说清就直接说清，需要展开的论证可充分展开。移除本次范围内的统一FREE绝对字数上限（当前发布计划85字）、统一句数和短窗阶梯多重取小，不制造“必须随机长短”或固定句数轮换。短剩余窗口仍优先完成一个有用回应；完整固定时段允许更充分总结。

四个常用 Agent 的差异应落实到论证选择和听感，而非口头禅：

| Agent | 优先表达与贡献 |
| --- | --- |
| 执锋 | 抓住决定性问题，正面回答后作精准反击；可短促有力，也能把关键证明讲完整 |
| 博闻 | 以准确证据、贴切例子和机制解释使主张可理解；不堆材料，不捏造出处 |
| 睿断 | 用明确的条件、利弊和选择后果完成判断；避免所有段落都停在“尚待验证” |
| 明辨 | 统摄真实分歧，把价值、人的处境与本场交锋连成有说服力的结论；感染力有论证支撑 |

其余当前身份沿用 Spec308 的完整专业底座，在同一195槽范围内保留各自合理表达偏好，不修改其他阶段或决策模板。所有身份/持方、typed JSON history、SELF/TEAMMATE/OPPONENT、PROVISIONAL/PENDING和管理员占位防注入边界保持。

### 3.3 时间规则保持

用户允许一定量超时截停，指接受现有 TIME_LIMIT 的结果，不是授权延长时钟、透支下一阶段或改变收尾协议。真实可用秒数仍来自 Core。原 `max_tokens`、模型生成参数、实时 `seconds × frozen_cps × 0.85` 估计、模型版本和音色参数完全不变；若原 token 上限造成截断，记录为该边界下未解决，不能擅改核心。

不以“越短越好”评审，也不以“字更多”代表质量。发布验收取消95%/100%自然结束硬率，但常规窗口反复未读完、固定结辩普遍截停或多数AI发言被截停仍视为未满足要求，须继续调整配置并复验。

## 4. 舞台、头像与状态文案

### 4.1 始终保持选手头像

候场、主持、倒计时、Agent思考/决策、待发言、正在发言、收尾、暂停、恢复、结束时，同一选手保持其原配置头像。思考不换 Bot、不随机、不隐藏图片；手机尺寸保留缩小头像。

这不是禁止用户正常更新资料头像。原头像版本/房间快照读取语义保留；原本缺失或加载失败的回退仍可使用，不由思考/发言状态触发回退。所有正常已配置头像须验证实际加载，不能只检查存在 `<img>`。

中心在已选中 Agent 准备时使用同一头像、姓名和“Agent 正在思考中”。队内 DECIDING 的文字和可见权限沿用原权威投影，不额外展示原权限不可见的队内决策信息。

### 4.2 状态清楚且专业

| 既有权威状态 | 展示 |
| --- | --- |
| Agent准备 | 原头像＋“Agent 正在思考中”，无发言波形 |
| Agent正式发言 | 原头像＋“Agent 实时发言中”＋原计时/波形 |
| 真人正式发言 | 原头像＋“人类实时发言中”＋原计时/波形 |
| 主持串场 | “主持人串场”，配当前阶段/已有实际阶段内容，保留适度声音状态表现 |
| 开始/恢复倒计时 | 原服务端倒计时数字为主，配当前阶段；下一位/阵营/辩位仅取现有公开快照明确字段，缺失则省略，不预测后续动作 |
| 真人待开始/收尾/暂停 | 准确表达实际状态；不伪称已开麦或仍在发言，必要操作提示保留 |

不展示主持真实音色名“龙风月瑶”、“主持音频播放中”、“请听取本阶段提示，播报结束后进入下一环节”、“正式发言计时尚未开始”等观众无用文案。不删真实错误、设备问题、管理操作和无障碍所需说明。不新增虚构的主持稿/倒计时、自动开始承诺或前端阶段预测。

### 4.3 沿用现有颜色和布局语言

- 顶部“当前阶段”使用现有绿色墨色 `--jx-lime-ink`，当前阶段标题清晰靠上，保持赛事信息层级。
- 主持与倒计时使用现有淡绿基调、适当边界和留白：阶段眉题→主要状态/大数字→已有真实上下文。解决卡片过空，不靠增加提示废话、重复八席姓名或多块空框填充。
- 正方卡使用 `--jx-red-soft`，反方卡使用 `--jx-blue-soft`，配同阵营浅边框和深色文字；保持轻盈。当前正式发言卡保留阵营底色，以更明确边框/侧标/现有绿色强调协调选中状态。准备/举手与真实发言仍有区别，不能改变谁是当前发言者的判定。
- 大屏和普通模式一起验证，保持品牌、大屏顶栏精简、Esc退出、辩题长文本与中央/八席稳定尺寸。动画只使用 transform/opacity，尊重 reduced-motion；不增加依赖、远程字体或新的图片素材。
- 大屏以会场远距离阅读为目标，1920×1080验收参考：阶段标题至少32px、主要状态至少24px、主计时至少96px、倒计时至少128px、席位头像至少64px、席位姓名至少26px、辩位至少18px。1440p/4K随视口增大，1280×720允许适度缩小但八席与核心信息完整。用舞台顶部、中心主要内容和辅助信息的明确分区展开布局，不将普通桌面小组件堆在中央；宽屏和超宽屏均实际截图核尺寸、分布及空白比例。
- 色彩不是唯一状态信号，保留姓名、辩位、状态文字；正常文字对比至少4.5:1，大字至少3:1，不能以亮绿色小字牺牲可读性。

## 7. 验收与证据

### 7.1 内容质量、长度、完整生成分列

冻结当前已发布 V12 基线、两开发题及一独立留出题、真实历史、双方持方、四Agent、音色、原参数与评分表。只变模板，匿名排列 A/B；不按较短/关键词/固定格式打分。

- 开发集：2题×双方×四Agent的16对总结，另8对FREE，平衡四身份/双方及原10/15/30秒窗口。
- 候选冻结后：第3题8对总结＋4对FREE，合计36对。逐篇全文独立评阅，保留每次输出、失败、版本与输入来源；留出失败不能通过同槽反复抽样换成通过。修改候选后重标版本并建立新的独立验证边界。
- 12对FREE按预先固定清单作边际平衡：每身份覆盖10/15/30秒各一次，双方总数均衡，开发8对/留出4对；不冒称身份×双方×时长全交叉。提前绑定rule/stage/agent/voice UUID、预算、真实messages/template SHA及原max_tokens/参数，候选请求须来自正式 `_load_config` 路径。
- 评审记录改善/相当/退步及具体原句证据：是否忠实承接争点、完成证明/回应、比较同一尺度、承担真实代价并给出有依据的结论；是否增加实际贡献、口语听感与表达变化。捏造事实/交锋、翻方、否定条件倒置单独阻断，不用均分遮盖。
- 总结与FREE分任务评分，上述项目按阶段和当前贡献适用。短应答、追问、叙事或类比不必每轮同时具备比较、代价与结论，以当轮有效贡献判定，不能由验收再次强迫统一论证格式。
- 发布至少能展示双方总结的净改善，四身份无持续性退步；若仍以短口号代替真实交锋，不能宣布满足需求。小样本不能证明“顶级辩手”或稳定可辨人格；记录独立Agent评审与真人盲听的区别，不冒称真人已验收。
