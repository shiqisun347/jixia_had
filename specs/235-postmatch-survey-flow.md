# Spec 235：赛后问卷阶段化流程与下一场门禁

## 状态

已发布（2026-08-30）；其中“整场体验先于发言审阅”的交互已由 Spec 236 取消，
完整记录与完赛提醒以 Spec 237 为准。

## 范围

- 赛制快照开启赛后问卷时，比赛 `FINISHED` 后为每位真人辩手创建唯一赛后任务。
- 赛后页面按单场比赛展示，先完成整场体验五题，再进入本方发言审阅。
- 发言审阅按阶段、阵营和发言者分组展示；AI 发言继续保持发言前判断先于实际文本解锁。
- 正式实验批次进入后续场次前，由 Core 检查该用户在同一批次已结束且启用赛后问卷的场次是否已提交。

## 不在范围

- 不改变个人 AI 感受问卷的独立生命周期。
- 不迁移或重写历史 Q1-Q5/ParticipantAnnotationTask 数据。
- 不改变比赛状态机、计时、媒体协议或既有 migration。

## 行为与接口

赛后任务仍使用 `PENDING/IN_PROGRESS/SUBMITTED`。保存接口增加可选 `stage`：

- `stage=overall`：校验并保存整场五题；允许任务保持 `IN_PROGRESS`，不返回或展示完整逐段内容。
- `stage=speeches`：要求整场五题已存在，并按现有规则校验全部逐段答案；`submit=true` 时任务变为 `SUBMITTED`。
- 未提供 `stage` 的旧客户端继续使用原子提交兼容路径。

Core 的实验进入接口在创建/进入正式场次时，阻止同批次中较早结束且赛制快照开启赛后问卷、但该用户任务不是 `SUBMITTED` 的场次。训练场次和无问卷快照不受影响。

## UI 验收

- 赛后入口以“待完成比赛”列表进入单场流程；整场体验通过每个任务独立链接进入，不在发言审阅页面或个人 AI 感受页面中混合展示。
- 阶段导航明确显示“整场体验 / 发言审阅”，未完成整场体验时发言文字和音频不可见。
- 发言审阅按阶段分组，正反方使用稳定的视觉标识，卡片显示席位、AI/人类标签和时间；长记录可折叠。
- 移动端无横向溢出，保存/提交失败显示可操作提示。

## 验收与回滚

- 服务端测试覆盖整体阶段保存、未完成整体阶段拒绝发言提交、完成后提交、同批次下一场门禁、旧客户端兼容。
- Web 测试覆盖阶段切换、阶段/阵营分组、AI 文本解锁和任务提交。
- 回滚仅撤销本规格新增的接口分支、门禁查询和页面；保留已有任务及答案数据可读。
