# Spec 241：自由辩论赛后标注对话工作区

- Version: v2.0
- Status: Released to production
- Date: 2026-08-30
- Depends on: Specs 222, 237, 238

## Goal

将单场赛后发言问卷收敛为只标注自由辩论发言的连续审阅流程。辩论记录以正反方对话
气泡呈现，问题与记录分离；答案自动保存，当前段完成后自动推进，已完成段可通过点击
气泡重新编辑。

本规格不合并账号级 AI 辩论体验问卷，不修改比赛结束门禁，不改变 Spec 222 已确认的
题目、选项及 AI 发言防止后见之明规则。

## Annotation Scope And Compatibility

- 只有阶段类型为 `FREE_DEBATE` 的 `HUMAN_SELF` 与 `TEAM_AI` 发言生成标注目标。
- 立论、质询、总结及其他非自由辩论发言仅作为已发生的上下文展示，不产生问题，也不
  计入完成进度。
- 规则判断使用房间冻结快照中的阶段类型；缺失或无法识别的阶段不默认为自由辩论。
- 所有未提交任务立即采用新范围。已有非自由辩论答案保留在原始数据和审计记录中，但
  不展示、不计入进度、不阻塞提交。
- 已提交任务保持其提交时的题目范围和答案快照，可按历史版本读取，不重新计算完成状态。
- 不修改历史 migration，不删除或重写任何问卷答案。

## Core Workflow

- Core 继续作为正文可见性和当前标注目标的唯一权威；Web 不使用公开比赛记录补全被隐藏
  的未来内容。
- 单任务投影只返回当前目标及其之前已发生的发言；未来气泡、阶段、发言者和正文均不进入
  普通参与者响应。管理员现有数据权限不变。
- 当前目标按自由辩论中的真实发言顺序选择。对方及其他真人/AI 发言只作为上下文，不产生
  问题。
- `HUMAN_SELF`：Q1 单选成功保存后进入 Q2；Q2 多选每次变化均保存草稿，但只有用户执行
  “完成并继续”后才确认本段并推进。
- `TEAM_AI`：Q1 单选成功保存后才返回该 AI 实际发言；Q2 单选成功保存后确认本段并推进。
- 服务端必须区分“答案草稿已保存”和“本段已确认完成”。确认状态持久化在任务现有 JSON
  数据中，不新增表或 migration；旧任务缺少确认元数据时，完整的旧版 Q1/Q2 按已确认处理。
- 保存与确认均幂等，并携带任务版本或等价并发栅栏；旧响应、重复点击和较早请求不得覆盖
  新答案或令界面倒退。
- 保存失败时不推进、不解锁下一段；返回可重试错误，同时保留当前服务端权威进度。
- 所有目标确认后仍保持草稿状态。用户显式提交整份问卷后才解除下一场门禁。

## Desktop Experience

- `/me/postmatch-surveys/[taskId]` 仍只对应一场比赛。
- 顶部保留比赛信息、自由辩论标注进度、保存状态和任务状态。
- 主体左侧是固定高度、内部滚动的实时辩论记录式对话框，不再使用阶段卡片、折叠面板或
  可见的未来占位。
- 阶段只使用轻量分隔标题；阶段始终展开。正方发言靠左，反方发言靠右，每次发言为独立
  气泡，并显示发言者、席位、真人/AI、顺序和时间。
- 当前目标气泡有明确但克制的高亮；完成当前段后，对话框自动滚动到新目标。
- 右侧 sticky 面板只显示当前问题、保存状态、错误与操作，不重复显示实际发言正文。
- AI Q1 保存成功后，实际正文只在左侧原气泡中解锁；右侧随即切换到 Q2。
- 单选题选择后立即保存；除 `HUMAN_SELF` Q2 外，保存成功后自动进入下一步或下一目标。
- `HUMAN_SELF` Q2 勾选变化实时保存，使用“完成并继续”确认，不显示“保存”按钮。
- 点击任意已标注目标气泡进入编辑模式，载入原答案并实时保存。点击“完成修改”后返回
  进入编辑前尚未完成的目标；修改不得重新锁定正文或回退进度。
- 最后一段确认后，右侧显示完成摘要和唯一的“提交本场问卷”命令。

## Mobile Experience

- 使用单列对话记录，当前目标自动滚动到可视区域。
- 问题使用底部面板；可收起查看上下文，但不得遮挡当前气泡，也不得产生横向溢出。
- 保存成功后同步切题和滚动。编辑、失败重试和最终提交行为与桌面一致。

## Failure And Audit Semantics

- 选择后显示“正在保存”；只有服务端成功响应才能更新已保存状态、解锁正文或推进。
- 保存失败保留本地选择并显示可操作的“重试”，不得静默丢失或假装完成。
- 离开存在未成功保存的选择时必须给出明确提示；已成功自动保存的草稿无需额外确认。
- 草稿保存、段落确认、已完成段修改和最终提交继续写入现有问卷审计链路。
- 普通用户只能读取和修改自己的任务；任务、比赛、参与者及问卷版本校验保持不变。

## Test Plan

### Core

- 只有自由辩论 `HUMAN_SELF`、`TEAM_AI` 成为目标，其他阶段仅作为上下文。
- 未提交旧任务立即排除非自由辩论目标，保留旧答案且可正常提交；已提交任务保持原快照。
- 普通参与者响应不包含未来阶段、发言者、气泡元数据或正文。
- AI Q1 保存前正文不可见，成功后可见；Q2 成功后推进。
- 真人 Q2 的部分多选可保存但不推进，“完成并继续”后才推进。
- 草稿保存、段落确认和最终提交幂等；并发旧请求不能覆盖新答案或回退确认状态。
- 保存失败不推进；重新请求能恢复服务端权威的当前目标。
- 编辑已完成段不重新锁定正文，不改变原当前目标；最终提交仍要求全部目标已确认。

### Web

- 左右气泡、阶段分隔、阵营、席位、真人/AI、顺序和时间清晰，阶段不可折叠。
- 页面不渲染未来发言及其元数据；右侧不重复实际发言正文。
- 单选自动保存和推进；真人多选实时保存并通过“完成并继续”推进。
- 当前段完成后自动选中新目标并滚动；刷新后恢复相同服务端进度。
- 点击已完成气泡可修改，完成修改后返回原待办目标。
- 保存中、成功、失败、重试、无自由辩论目标和最终提交状态均有明确反馈。
- 桌面 sticky 问题面板及移动端底部面板无重叠、遮挡或横向溢出。

### Release

- 运行 Core 问卷测试、独立 PostgreSQL 集成测试、Web 单测、Storybook、类型检查、Lint、
  OpenAPI 契约检查、生产构建及专项 Playwright。
- 使用包含双方真人/AI、多次自由辩论发言的任务完成：自动保存、失败重试、刷新恢复、编辑、
  最终提交和下一场门禁解除。
- 发布前备份生产服务与数据库并确认无非终态比赛；发布后验证参与者隔离、详情页、提交门禁、
  服务健康和 warning 日志。

## Rollback Boundary

- 回滚 Web 对话工作区和 Core 新投影/确认语义时恢复同一版本的完整构建。
- 保留新增在任务 JSON 中的确认元数据，由旧代码忽略；不得删除问卷任务、答案或审计记录。
- 不回滚数据库 migration，因为本规格不新增 migration。
