# Spec 290：参与者标注答案请求体护栏

状态：本地实现完成，待受保护发布

## 问题

Spec 288 限制了标注响应，但参与者保存答案的 `answers` 字典仍没有独立的键数量和逻辑
JSON 字节上限。异常客户端或恶意请求会先被 Pydantic 解析，再进入业务校验和事务路径，
放大 Core 请求内存与数据库日志压力。

## 范围与验收

- `ParticipantAnnotationAnswerSaveRequest.answers` 最多包含 4 个键，紧凑 UTF-8 JSON 最大
  64 KiB；超过时在请求模型阶段以可理解的 422 错误拒绝，不进入事务。
- 正常两阶段答案结构、字段名和响应保持不变；不改变权限、比赛状态或数据库 schema。
- OpenAPI/TypeScript 契约同步，覆盖键数量、字节上限和正常答案回归测试。

## 验证证据

- Core 标注测试覆盖键数量和 64 KiB JSON 上限；`test_experiments.py` 17 项通过。
- 契约检查、Ruff 和 Pyright 通过；未写生产数据库、未重启或发布。

## 回滚边界

仅回滚请求模型、契约生成物、测试和本规格即可恢复旧输入行为，不删除数据，不涉及生产
数据库写入或服务重启。
