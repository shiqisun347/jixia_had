# Spec 261：真人 4v4 比赛与现场运维

状态：已完成本地验收并完成线上发布（2026-10-01）

成员组成说明：本规格发布时的“每方 2 真人 + 2 Agent”门禁已由 Spec 265 取代；当前正式 4v4
仍固定双方各 4 席，但允许纯真人、纯 Agent 和任意混合比例。本规格的大屏、现场控制台及其他
运维约束继续有效。

## 目标

把产品入口从论文实验工作流收敛为可现场执行的人机辩论赛：每场新比赛为正反双方各 2 名真人和 2 名 Agent，管理员可以把比赛页切换为大屏展示，并能在突发故障时通过后台控制台执行可审计的恢复操作。

## 范围

- 普通新建房间固定为正式 4v4；启动前 Core 强制校验每方 `2 HUMAN + 2 AGENT`，并保留历史实验/非 4v4 数据只读兼容。
- 移除普通用户和管理员导航中的论文实验、实验预约、排表、专家标注和研究导出入口；历史接口不因本规格删除数据。
- 比赛页为管理员提供“大屏展示”入口：进入浏览器全屏、隐藏编辑/操作控件、突出双方席位、当前发言、阶段和双边剩余时间；退出全屏后恢复正常控制视图。
- 后台提供现场控制台：实时状态、当前发言与在线设备、最近错误和关键事件，并支持暂停/恢复、恢复保护、重置当前发言、强制终止；每项操作沿用 MatchActor、幂等消息和审计日志。
- 建立一套可重复的双真人双 Agent 端到端模拟：建房、四真人入席、设备检查、开赛、固定发言、自由辩论、Agent LLM/TTS、真人 ASR、暂停/恢复、超时和终止恢复。

## 验收

- API 和 Web 都无法创建或启动非 4v4、全 Agent 或单方真人数量不是 2 的新比赛。
- 4 个真人测试身份和 4 个 Agent 席位（每方 2 + 2）能够完成完整赛程，比赛达到 `FINISHED`，每个阶段有关键事件和非空文字记录。
- 注入 LLM/TTS/ASR 超时、断线、迟到回调和重复命令时，比赛不死锁；按既有语义暂停或进入可恢复状态，恢复后继续推进或安全终止。
- 管理员大屏入口和事故控制台通过桌面浏览器验证；移动端不作为大屏验收目标。
- Core/Jobs/Web 标准门禁、专项模拟器和浏览器测试通过；未执行的真人噪声、五场压力和 50 路负载继续明确标为待验收。

## 真实验收证据

- 本地 PostgreSQL + 当前 migration 下，正式 4v4 持久化集成 5/5 通过；新增房间服务集成实际完成四真人入席、设备检查、准备和启动，四个 Agent 席位保留。
- Core HTTP 本地启动后 live/ready 均为 200，未认证边界返回 401；5 轮正式 4v4 回放完成 50 次发言，Spec 258 的 31 个 ASR/Agent/TTS/暂停恢复/超时/幂等场景全部通过。
- 旧论文 migration/all-agent 集成测试仍保留作历史回归，其断言与 v2.0 新入口不再一致，不作为正式比赛验收门禁。

## 回滚边界

- 只回滚新增 UI、校验和控制台代码；不删除历史实验表、比赛、文字记录、音频或审计事件。
- 运行中的比赛不得通过发布脚本强制终止；发布前必须确认无非终态比赛，异常比赛使用后台控制台处理。
- 不修改既有 migration；若需要新增数据库字段，另写追加 migration 并独立验证。
