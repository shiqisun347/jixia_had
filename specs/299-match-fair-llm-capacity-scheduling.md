# Spec 299 — 比赛公平 LLM 容量调度

- 版本：v2.0
- 状态：设计草案，待批准；未写业务代码
- 日期：2026-10-13
- 依据：TechDesign §8.2；Spec 274 的并发与资源清理复审。

## 问题与目标

目前 Agent 正文、自由辩论决策、AI 裁判和后台模型测试已共享全局与模型硬上限，
但 limiter 只知道模型键，不知道比赛和调用角色。Semaphore 的到达顺序无法保证
比赛轮转，也无法保证活动比赛发言/决策优先于裁判、裁判优先于后台测试。
Spec 274 的 model-first 获取和共享容量修复没有完成这一要求。

本规格只补齐 Core 内的等待调度；不抢占已经运行的模型 stream，不改变发言权、
比赛状态机、媒体计时、模型选择或重试次数。

## 最小设计

1. 复用应用唯一的 LLM 容量组件，维护全局与 ModelProfile ID 的在用计数。
   在同一短临界区同时检查、授予两层名额；等待者不预占任一层名额。
2. 由 Core 调用者传入角色及权威关联：正文/决策为 ACTIVE，裁判为 JUDGE，
   管理连接测试为 CONFIG_TEST；比赛 ID 来自现有准备任务或服务上下文，不接受
   浏览器提供的优先级。后台测试按模型资源 ID 分组。
3. 在可同时满足全局和模型容量的等待项中，按 ACTIVE > JUDGE > CONFIG_TEST
   选择；同一角色内按比赛轮转，每轮每个比赛最多授予一项，同组可运行项按入队
   顺序选择。已满模型的项可暂时跳过，即使它是同组队首，也不阻挡其他可运行模型。
   新请求也经过同一调度路径。
4. 等待总数最多 64；每个角色/比赛组最多 8；CONFIG_TEST 总等待数最多 8。
   队列只保存关联 ID、角色、模型预算、单调截止时间和 Future，不保存 prompt、密钥
   或媒体。队列满直接返回既有 `llm_capacity_full`，不新增重试或静默降级。
5. 排队仍从请求容量起共用最多 3 秒绝对预算，含调度锁等待；超时和取消移除等待项，
   不留下容量或轮转条目。授予后、调用者尚未恢复执行时发生取消或超时，也须恰好
   回收一次已授予 lease。释放继续同步且必须幂等，全局与模型计数不能变负、超限
   或重复归还；空组与轮转游标必须收敛。
6. 沿用 Spec 274 的 stream 结束立即释放及有界客户端清理；调度结果不推进比赛，
   后续回调仍接受原有身份栅栏。组件不新增常驻轮询任务、数据库表或外部服务。

## 验收切片

先验证容量组件，再分别接入正文/决策、裁判、后台测试，每一切片单独运行对应回归。

- 五场合成比赛同时排队时，在持续可用的同一模型上按比赛轮转；单场多个候选不能
  越过其他已等待的比赛。跨模型满载不得造成空闲模型阻塞，同一比赛队首模型满、
  后项模型空闲的场景也须验证。
- 同时已有三类等待项时，下一可用名额先给 ACTIVE，再给 JUDGE，最后给测试；
  不中断已运行的低优先级 stream，也不为不满足模型预算的项保留空闲全局名额。
  ACTIVE 模型已满而 JUDGE 可运行时允许 JUDGE 获得容量；ACTIVE 可运行后，下一次
  授予优先 ACTIVE。
- 50 全局上限与模型独立上限始终有效；64 全局队列、8 分组和8测试等待上限均验证。
- 默认 3 秒绝对截止、队列满、取消、释放/取消竞态、重复释放及大量重复轮次后
  在用/等待计数和轮转条目全部恢复；原错误码、取消及失败语义不变。
- 真实调用路径回归验证角色和比赛 ID，后台 HTTP 仍保留认证、Origin 和错误契约；
  Agent/裁判清理与迟到回调回归、完整 Core 测试、Lint、类型及 contracts 通过。
- 合成 50 路和五场只作为逻辑证据。发布前仍须在受保护目标环境完成 50 路真实
  stream、单独后台测试路由，以及真实五场媒体压力；未执行的检查明确记为待验收。

## 非目标与限制

- 不修改认证/权限、数据库 migration、比赛数据、媒体协议、模型/音色或重试策略。
- 不引入 Redis、Kafka、微服务或跨进程调度。
- 严格角色优先级可能推迟裁判和后台测试；保留其现有 3 秒容量失败，不能悄悄增加
  aging 或其他优先级策略。忙模型本身的吞吐不足也不会被公平调度修复。
- 同模型冻结快照的不同容量版本冲突不在本规格中擅自重新定义。

## 回滚与发布边界

仅回退本规格的内部排队组件、调用者角色/比赛关联及对应测试；继续保留 Spec 274
的共享容量、取消归还、绝对截止、stream 后释放和有界清理。无数据库回滚。
生产仍须满足既有非终态房间/比赛门禁及受保护窗口，不自动终止真实比赛或重启服务。

按 AGENTS.md“未批准前不写业务代码”，本规格在批准前只保留设计和验证计划。
