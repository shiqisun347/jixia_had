# v2.1 论文实验闭环修复

> 状态：实现、服务器发布与服务端 provider chain 验收完成；正式实验启用仍受外部输入约束
> 日期：2026-08-22
> 依据：`paper_docs/需求对齐.md`、`paper_docs/开发指南.md`、Spec 201

## 1. 背景

Spec 201 已落地主要实验运行、标注和导出能力，但代码审计发现四个可直接影响
正式实验的闭环缺口：停用能力没有完整管理动作，训练题没有进入批次排表，排表
不能 CSV 往返，停用批次仍会显示给参与者。v2.1 只修复这些确定性缺口，并把
版本能力和文档状态同步到 v2.1；不改变普通比赛、实验状态机、计时或实时媒体协议。

## 2. 范围

### 必须实现

1. 管理员可将 `DRAFT` 或 `PUBLISHED` 批次停用。停用前拒绝仍有
   `CREATED/WAITING/RUNNING/PAUSED` attempt 的批次；停用后禁止新建/发布/进入 attempt，历史数据
   和管理员导出保持只读。
2. 管理员排表向导支持一个训练题，训练场次与正式 18 场分开保存，训练题不得进入
   正式分析和排行榜；发布时训练题必须存在且与 C1-C6 不重复。
3. 提供管理员 CSV 排表导入和导出：导入只写 DRAFT，逐行返回结构化错误；导出包含
   schedule version、kind、topic、双方队伍和八席位，往返结果可被同一校验器接受。
4. 参与者预约只读取 `PUBLISHED` 批次；`DISABLED` 批次历史只通过管理员接口读取。
5. 应用与能力响应版本、前端实验入口更新为 v2.1；既有 Prompt/问卷内容没有修改，
   因而保持原实验内容版本；停用后普通导航和历史管理员
   入口行为符合需求。
6. 管理员可在草稿批次一次性预生成或绑定 `P01-P18`、`E01-E03` 匿名账号；
   初始密码只在创建响应中返回一次，数据库只保存 hash，响应不得进入普通日志或导出。
7. v2.1 面向服务器在线发布：沿用 Core/Jobs/Web/PostgreSQL/LiveKit/反向代理拓扑，提供
   migration、构建、systemd 重启、健康检查、实验能力检查和前向兼容回滚步骤；不得把
   本地测试数据库、临时密码或服务凭据同步到服务器。

## 3. 非范围

- 只追加 migration 0029；不修改 0001-0028，也不在本规格中追加新的数据库变更。
- 不实现伦理文本审批或真实服务凭据交付；这些是发布输入，v2.1 必须在管理校验中
  清晰报告缺失。
- 不改自由辩论竞争算法、Agent Prompt 内容、ASR/TTS、LiveKit 或普通比赛路径。

## 4. 验收

- Core service 单元测试覆盖停用前活动 attempt 拒绝、停用后所有 mutation 拒绝、
  参与者预约过滤和训练题约束。
- CSV 导入/导出纯函数测试覆盖空文件、重复席位、未知队伍、非法 occupant、公式
  注入和稳定列头。
- API 契约和 Web 管理向导测试覆盖训练题、导入/导出、停用按钮与能力版本。
- `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm contracts:check`,
  `pnpm test:storybook`, `pnpm test:browser`, `pnpm build` 通过。
- 独立 PostgreSQL 对 0029 migration 和 v2.1 管理闭环执行真实集成测试；服务器发布前
  验证 migration head、`/health/live`、`/health/ready`、`/api/experiments/capabilities`
  与管理员实验页，发布后观察 warning-or-higher 日志。
- 无 PostgreSQL 时必须明确报告数据库集成未执行，不得用 mock 结果替代真实迁移证据。

## 5. 回滚

v2.1 只新增应用代码和 OpenAPI 字段，不修改 0001-0029 migration。应用回滚到
v2.0 时忽略新增 CSV/disable 路由即可；已停用的批次保持 `DISABLED`，不得自动恢复或
删除历史实验数据。
