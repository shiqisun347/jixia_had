# 207 后台框架与全局资源基础

> 版本：v2.1  
> 状态：已完成并验证  
> 批准依据：用户要求按五阶段分别编写并批准规格后持续开发、测试（2026-08-22）  
> 依赖：200、206，根 PRD 第 14 节，TechDesign 及 `paper_docs/变更.md`  
> 本阶段现已解除规格门禁，可按本规格实施。

## 1. 目标与范围

建立统一的桌面后台 Shell、权限边界、运营概览、全局资源列表和编辑交互基础。覆盖单一系统管理员、普通用户隔离、用户/模型/音色/辩题/系统设置资源，以及统一表格、筛选、抽屉、确认框、Toast、加载/空态/错误态。

不实现赛制版本工作区、运行日志新数据管道、批次新生命周期或移动端后台。

## 2. 现状复用与冲突门禁

- 复用 `apps/web/src/features/admin/admin-shell.tsx`、`admin-data-table.tsx`、`admin-controls.tsx`、`ConfirmDialog` 和现有 Core 管理认证。
- 当前 PRD 将 Agent 列为全局资源；本方案只在后续 209 规格中迁移 Agent 到赛制版本。207 不改变 Agent 数据归属。
- 当前用户删除、密码修改和 API Key 展示规则以 PRD/TechDesign 为准，207 只统一交互和审计入口。
- 若发现后台管理员数量、Origin 校验或审计事务与事实来源冲突，停止对应切片并记录冲突。

## 3. 信息架构

实现以下一级导航和路由占位：

```text
/admin                       运营概览
/admin/users                 用户
/admin/models                模型
/admin/voices                音色
/admin/topics                辩题
/admin/settings              系统设置
/admin/formats               赛制中心（由 209 接管）
/admin/matches               比赛与数据（由 210 接管）
/admin/logs                  运行日志（由 210 接管）
/admin/incidents             事故（由 210 接管）
/admin/tasks                 后台任务（由 210 接管）
/admin/audit                 审计日志（由 210 接管）
```

### 验收

- 管理员登录后只能看到后台导航；普通用户访问任一路由或 API 均得到统一 403/401，不渲染管理数据。
- 运营概览展示活动比赛容量、启用模型/音色/规则数量、待处理任务/事故、磁盘门槛和最近比赛，并可跳转对应列表。
- 当前页面、筛选、排序、分页、加载失败和空态均可恢复；刷新不会丢失 URL 查询条件。

## 4. CRUD 交互契约

- 简单资源最多约 8 个字段使用新增/编辑弹窗；长文本、分组配置和子资源使用独立工作台。
- 只读详情与敏感详情使用右侧抽屉；删除、停用、密码修改、API Key 轮换使用确认弹窗。
- mutation 期间禁止重复提交；成功后刷新相关 TanStack Query 缓存；失败保留输入并显示可操作错误。
- 表格统一提供搜索、状态筛选、排序、数量、分页、明确空态和行操作菜单。
- 不提供危险资源的批量删除、批量发布或批量密码修改。

## 5. 全局资源边界

### 用户

- 仅管理员可增删改查、启用/停用和修改密码；有历史关系的用户不可物理删除。
- 修改普通用户密码后撤销该用户全部会话；管理员修改自己的密码保留当前会话并撤销其他会话。
- 密码和 token 永不进入列表、日志、导出或错误响应。

### 模型与音色

- 继续作为全局资源；编辑、停用、连接测试、试听和校准均记录审计。
- 被活动比赛引用的运行字段继续锁定；停用替代删除。
- API Key 只在显式管理动作中显示，日志仅保存脱敏凭据版本。

### 辩题

- 全局辩题维护保留在本阶段；赛制引用和私有快照由 209 接管。
- 删除前检查历史引用；有引用时只允许停用或修改非事实元数据。

## 6. 回滚与验证

- 仅新增路由、组件和兼容查询，不新增 migration；可通过路由开关恢复旧后台入口。
- 验收覆盖管理员/普通用户权限、CRUD 弹窗、错误/空态、键盘焦点和 `1280x720`、`1440x900`、`1920x1080`。
- 必须运行 Web lint、typecheck、单元、Storybook、浏览器和生产构建；Core 认证/审计相关测试不得回归。

## 7. 实施证据

- 后台导航已按“概览 / 资源 / 赛制 / 比赛 / 运行与诊断 / 系统”重组；旧 Agent、规则、裁判与实验页面仍可通过赛制中心迁移入口访问。
- 新增赛制中心、裁判结果、事故、后台任务和审计日志路由；事故和任务复用现有诊断 API，未伪造新数据源。
- 后台固定为桌面工作台，页面级横向内容由壳层裁剪，宽表继续在自身容器滚动。
- Web 单元测试 174/174、Storybook 86/86、完整 Playwright 216/216、ESLint、TypeScript 和仓库脚本生产构建通过；构建生成 34 个页面。
- `agent-browser` 在 `1280x720`、`1440x900`、`1920x1080` 验证导航和概览，无页面级横向溢出；Axe WCAG 2 A/AA 为 0 violations。
- 初次 Playwright 发现实验草稿删除后页面级横向溢出，修复后专项 4/4 和完整 216/216 通过；未修改 Core、数据库、比赛状态机或实时协议。
