# Spec 291：实验历史聚合护栏

状态：本地实现完成，待受保护发布

## 问题

Spec 284 为实验批次和预约接口增加了有界游标分页，但兼容服务 helper 与 Web 便利层仍会
自动追完全部历史。正常历史持续增长，或上游反复返回新的游标时，调用方可能无限发起请求并
持续保留数组、ORM 对象和 JSON，最终拖垮 Core 或浏览器；重复游标只能覆盖其中一种异常。

## 范围与验收

- `list_batches` 与 `list_appointments` 继续返回完整历史语义，但最多聚合 200 页/10,000
  条；超过上限、游标回环或游标不前进时使用稳定的
  `experiment_history_too_large`（HTTP 413）或查询错误失败，不返回被截断的部分数组。
- Web 批次和预约全量便利层继续自动消费分页，单次最多 200 页/10,000 条/16 MiB UTF-8
  JSON；超过上限、响应不是数组、游标重复或不前进时显式失败，不静默隐藏历史。
- HTTP 分页接口、游标顺序、单页响应字段和现有客户端数组形状保持兼容；需要更大历史时，
  调用方仍可直接按游标逐页读取，不删除或截断数据库数据。
- 覆盖 Core 两个兼容 helper 的异常收敛，以及 Web 的数组校验、重复/不前进游标和总量护栏。

## 非目标

- 不改变实验生命周期、权限、排序、分页游标编码或数据库 schema。
- 不把全量历史改成摘要、不删除历史，也不修改既有 migration。
- 不执行生产写入、服务重启或发布。

## 回滚边界

仅移除聚合护栏、响应校验和对应测试/文档即可恢复原有自动聚合；HTTP 分页和实验数据不受
影响。
