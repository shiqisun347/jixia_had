## 3. 切片 A：连续真人收音与有界 ASR 恢复（P0）

### 3.1 音频消费不等待诊断和旧段持久化

- 先用真实 180 秒 TTS 输入比较当前 3.1 与官方 3.0 流式 WebSocket，同一音源、实际墙钟发送、实际 final。记录连接/首结果/收尾延迟、样本数、文字覆盖和错误码。
- 优先现有百炼工作空间专属 WebSocket。官方 3.0/3.1 均支持不限时长输入；不能继续把旧 FunASR 的 30 秒约束当作新模型强制要求。
- 依据实测选择一次：使用已验证的单发言连续 task，或保留有界分段并解耦旧段收尾。若使用连续 task，其总预算由本次权威最大音频时长加收尾预算导出，不再固定 35 秒。若分段，旧段 final/采集/落库不阻塞新 PCM 消费，段序与文本提交仍严格有序。
- 不仅增大队列掩盖阻塞；所有输入、重放与在途 task 有明确帧/字节/数量上限。复用现有真人录音资产作为恢复来源；新增暂存预算按正式最长发言、16k 单声道 PCM16 推导并实测，终态清理。不无界内存积压、不静默丢帧、不以消费者失败后重喂掩盖生产故障。
- 业务分段持久化与非权威诊断写入隔离，沿用 Spec300 有界 writer。诊断失败不得撤销正常识别或卡住实时队列。

### 3.2 技术失败不重置整次发言

- 首次可恢复 ASR 错误只退役所属识别 task，保留 speech/attempt、已使用时间、连续输入和确认前缀，以新识别 generation 从未确认音频有界重放一次；不得重复拼字、重复记时或更换供应商/模型。
- 有效音频不能保存或恢复预算用尽时，Core 明确冻结当前必要发言并说明原因；不在“正在整理”上无限等待，不把缺失文字当作成功完成交给 Agent/裁判。管理员可重试识别、显式重置或安全占位；显式重置才产生新的发言尝试。
- 输入关闭时以单调时钟建立唯一整体收尾截止，默认 20 秒，覆盖在途重放、三秒连接恢复、final、保存、录音关闭、提交和清理；不可用几个独立 timeout 相加绕过整体预算。子任务、重连及 generation 更换不刷新截止，一次自动重放额度按同次 speech 计，不能每换 task 重新获得。达到截止进入带 source 身份的可恢复失败，后续显式重试是新的有界操作。
- 实时故障恢复允许已录音有界追赶，不要求辩手重新朗读；恢复不能按录音重放时长再次消耗比赛时间。没有音频则明确提示，不能生成假 ASR。
- 增加启动就绪和存活检查：RTC 首帧、ASR task-started、实际消费分别记录；没有有效 reader 不进入正常收音状态，不能只有计时而无 ASR。错误使用完整原始信封回到 Actor。
- 真实辩手页面的首次开麦不能与服务端准入互等：仅在当前合法真人显式点击后，以连接/epoch/当前发言动作/context绑定的pending-start claim先建立本人的真实麦克风并静音发布真实音轨，再发送既有speech.start；Core reader就绪不依赖首PCM，因此不得在权威确认前取消静音，让观众提前听到未计时/未记录声音。确认后才由仍合法的同一claim开声；不是预录静音假帧。等待开麦与ACK期间复验身份，页面重渲染不撤销合法claim；暂停、重置、换人、换连接或结束立即退役旧claim。迟到成功不得复活旧麦，迟到失败不得关闭新的合法麦；权限拒绝或启动失败关闭所属媒体并给可操作提示。Core计时仍从原权威提交起点开始，不预置原生publisher绕过真实网页。

### 3.3 所有权、清理与收敛

- ASR 的机会 ID 与机会代次必须成对归属于实际自由辩论机会。固定发言没有机会 ID，其回调的机会代次必须为 `None`；暂停、重置、跳过后用于退役旧机会的全局计数不能变成固定发言的机会身份。保留该计数、全部既有回调校验及真正自由辩论的持久机会代次，不通过放宽过期校验修复合法回调误拒。增加实际 Receiver/Session/Protocol/Actor/PostgreSQL 的重置后固定真人收尾红绿控制。
- 正常到时的媒体截止复用已提交 `speech.started`/`speech.media_ready` 中的 Core 绝对单调截止点。先向完全匹配的 Session 安装截止点和时钟，再允许 PCM 输入；不能把剩余毫秒在媒体端重新起算。到时帧在写入录音和识别缓存前停止接纳，但不提前结束供应商 task、不撤销合法 final 回调、不广播未提交状态；正常 `speech.finalizing` 提交后才发送 finish。唯一收尾截止从该权威输入截止点加20秒导出，有界 watchdog 必须唤醒仍在等待旧 recv timeout 的任务。
- 重连后非整PCM块的剩余预算只在有界历史容量上向上对齐到现有100ms块，例如88889ms的容量为88900ms；整块预算不增加，额外容量严格小于一个块。输入仍按原Core绝对截止封口，容量不成为计时或延长发言的来源。到时前最后合法完整块不得因毫秒取整被误报溢出；真正超过对齐容量、截止后输入及旧owner仍按原规则拒绝。
- 到时事件提交失败时，只有 `internal_timer_failed`、当前真人发言、已到权威截止且完整匹配旧 ASR owner 的窄分支，才可在保留原录音后转入既有 `asr.failed` 恢复入口；其他系统错误保持原语义。不引入通用事务回滚 hook，不自动重开麦克风；持续不可写时明确无法提交，未知提交确认结果不得覆盖历史。手动提前结束保持现有提交边界，不借正常到时修复扩展其事务语义。
- 校验完整 match/speech/attempt/generation/epoch/context/opportunity 身份。媒体输入 owner 与已经关闭输入、仍合法的 finalizer owner 分开冻结；正常新连接不能抹掉合法旧 final，reset/skip/暂停退役的旧结果依然必须拒绝。
- 取消、关闭和失败路径幂等；先阻止旧输入/回调，再有界回收 task/socket/track/文件，确认注册项属于旧 owner 才删除。不能用猜测的 attempt1/context0 替代捕获身份。
- 比赛启动请求与Actor在线状态提交同时操作同一Match和Room时，统一按Match→Room取得行锁，避免既有Room→Match预检与Actor提交形成数据库死锁。保留原权限检查、事务提交和Actor启动事件，不新增自动重试、不改状态机或计时起点。用真实Manager、Actor和独立PostgreSQL的锁后barrier强控制先复现40P01，再验证相同入口可以串行完成及既有错误/幂等语义。
- 收尾 watchdog 和背景异常必须进入权威命令，不能仅打印异常。跨回调/事务的锁顺序仅在可复现证据支持时调整；事务提交后才广播。
- 后续诊断记录实际 model、接入类别、分段和所有权阶段、输入/发送帧数、队列峰值、final/保存/清理耗时与脱敏原因；禁止正文和凭据进入普通日志。

模型选择必须有同源实测报告，结果未证明更优则保留当前 3.1。禁止运行时自动切模型、切供应商或伪造成功。保留当前 TTS/LLM 模型及主持声音，除非本规格下的显式 ASR 比较得出并冻结另一选择。

## 4. 切片 B：文字记录与界面状态（P0）

- REST 与 WS 共用单调 snapshot 接纳规则；迟到旧 HTTP/旧连接事件不得覆盖新序号、身份、计时及附属字幕。合法同序号多次临时字幕仍更新。
- interim 按公开 source speech 和有效连接归属；旧 source 的 final/clear 不能清新人的字幕。Core 如需投影上一段整理状态，只增加最小公开 source 字段，生成 contracts；不臆造当前契约没有的 context 字段，不泄漏私有决策。
- 新有效连接、恢复快照、`speech.skipped`、`stage.reset`、终态均合并同步正式 transcript；不依赖未来恰好再有一段发言，也不随每个 token 无界 refetch。
- 已加载的正式记录在 refetch/ASR/TTS 错误时继续可读；未保存活动段单独显示所属人及“识别中/整理中/保存失败”，不冒充正式发言或进入评分上下文。
- 初次空记录、请求失败、保存失败明确区分，提供可操作同步/重试；记录区域局部容错，不能因异常响应形状使整场页面卸载。认证失效仍遵循既有登录规则。
- 两真实浏览器（辩手、观众）同时核对 DB 正式投影与 DOM；只验证后台函数成功不算面板验收。

## 5. 切片 C：弱网容错与安全继续（P0）

- 不以 RTT、短丢包、单次 heartbeat 缺失暂停比赛。业务 WS 与 RTC 连接分别标识；WS 短断但有效音频持续时继续权威收音/计时，重连补同步。
- 同一媒体 owner 短暂抖动采用三秒有界恢复窗口；音频真实中断则保护当前真人余额、停止无效收音。媒体就绪后才恢复发言计时，且不能自动打开用户已关闭的麦克风。
- 当前必要真人长时间无法恢复时才局部阻塞；非当前真人和观众断线不全局暂停。保留 60 秒长期无法恢复的安全暂停边界，解除不必要的“所有辩手同时在线”恢复条件；必要参与者仍须权限、会话、设备与媒体检查通过。
- 普通恢复、管理员恢复和自动继续使用相同权威必要检查，不能直接套用现管理员跳过检查的入口。旧 epoch 的断线/恢复定时器不得作用于新连接。
- 明确提示“正在重连/当前麦克风待恢复/此人暂离”，让现场知道能做什么；不把所有弱网都写成供应商故障。

## 6. 切片 D：应急跳过与重置（P0）

- `跳过当前发言 · AI占位` 为一个带 operation ID/generation 的权威操作：冻结并隔离旧任务→回收媒体/ASR/LLM/TTS→真实 LLM 生成上下文占位→一次事务提交→安全检查→正常恢复倒计时/下一权威环节。
- 成功不再要求手动恢复；Web 不补发 resume 假装自动继续。比赛原先因其他原因暂停、已有新的暂停/重置/终止意图、必要设备未就绪或清理未完成时，不能让旧 worker 自动恢复。
- 占位明确标记“管理员 AI 占位、未播报、不计个人实绩”，无 TTS、无假冒真人原话；保留历史审计。LLM 失败/资源无法清理/整体截止到达时给出单一可重试失败，不携带旧任务进入下一环节。
- 适用于固定发言、自由辩论和四辩；一次跳过只结算/推进一次，不略过后续全部环节。重复点击、断线重发、服务恢复后的旧完成均幂等。
- 重置当前发言、阶段重置同样先退役再建立干净的新 owner/上下文/计时器；废弃文字不进入后续 Agent/裁判，合法历史仍保留。终态禁止恢复和重复评分归档。

### 7.2 明确的新决策等待规则
