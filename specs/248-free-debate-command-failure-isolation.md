# 248 自由辩论命令故障隔离

> 版本：v2.1
> 状态：已发布，真人全流程验收继续进行
> 批准依据：用户要求继续真实双人比赛验收，并修复生产中真人举手被泛化服务错误拒绝的问题（2026-09-02）。

## 范围

- 修复自由辩论中 TTS 已失败或比赛恢复后，真人 `hand.raise` 不得因内部异常获得泛化“服务暂时不可用”错误。
- WebSocket 命令向 MatchActor 保留已校验的 `connection_epoch`，使事件审计和迟到命令栅栏使用同一身份数据。
- 对未预期的 WebSocket 命令异常记录脱敏的异常类型、SQL 状态和约束名；不记录堆栈、供应商响应、提示词、Cookie 或任何密钥。
- 补充回归测试，覆盖人工等待阶段举手、连接 epoch 落库和异常命令的可诊断性。
- 修复等待房间中已加入辩手重连时的成员在线状态恢复；重新进入邀请码必须恢复
  `RoomMember.online`，并让房主可按既有准备条件启动比赛。

## 非范围

- 不改变 TTS 的一次重试、第二次失败暂停语义，不切换供应商或模型。
- 不改变 `HUMAN_WAIT_TIMEOUT` 的既有暂停规则。
- 不改已有 migration，不修改比赛时钟、房间权限或媒体协议。

## 验收

- 处于 `FREE_SELECTING/HUMAN_ONLY_WAIT` 的合格真人举手成功提交，并带当前连接 epoch 落库。
- 若命令路径仍有未预期异常，日志含足够的脱敏分类字段以定位，不向普通用户泄露内部细节。
- TTS 失败后的恢复及之后的人类命令遵循 MatchActor 的领域状态机，不返回泛化 500。
- 相关 Core 测试、类型检查和 lint 通过；生产部署后完成一次真实页面恢复/举手验证。

## 回滚边界

- 仅回滚本规格涉及的 Core 源码制品；不回滚、改写或删除已经产生的比赛、调用或审计记录。
