# Spec 292：Web 标注任务聚合响应护栏

状态：本地实现完成，待受保护发布

## 问题

Spec 285/288 将参与者与专家标注任务接口改成有界游标分页，并允许 Web 客户端继续自动
合并最多四页。`fetchTaskPages` 仍直接把服务端响应展开到一个数组，未校验响应形状，也未
限制跨页累计条数和 UTF-8 JSON 字节数。异常上游响应、错误分页实现或增长中的历史可能让
浏览器一次性保留超过 Core 设计预算的任务载荷。

## 范围与验收

- `fetchTaskPages` 每页仍请求 25 条并最多追踪 4 页；每一页响应必须是数组，否则以可理解
  的错误失败，不继续请求后续游标。
- 跨页累计任务数最多为 100（4 页 × 25 条），累计紧凑 JSON 的 UTF-8 字节数最多为 64 MiB，
  与 Core 标注单页 64 MiB 载荷预算对齐。超过任一预算时 fail-closed，不返回部分数组，
  不静默截断历史。
- 重复游标、超过页数和超出总量沿用现有可操作错误语义；调用方需要更多历史时可直接按
  游标分页读取，HTTP 契约和服务端字段不变。
- 不修改数据库、比赛状态机、权限、标注提交语义或 migration。

## 回滚边界

仅回滚 Web 客户端的总量/响应形状校验、对应测试和文档即可恢复原有最多四页自动聚合；
服务端分页、数据库数据和已有 Core 64 MiB 预算不受影响。

## 验证证据

- Web `experiments-api` 测试覆盖非数组响应、累计任务数、累计 UTF-8 JSON 字节数、重复
  游标和四页上限。
- Web lint、typecheck、Vitest、Prettier、生产构建和 diff-check 通过；未进行生产写入、
  服务重启或发布。
