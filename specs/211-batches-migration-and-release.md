# 211 批次、训练房间与历史迁移发布

> 版本：v2.1  
> 状态：已完成生产发布、线上服务/浏览器冒烟和供应商链路验证；正式真人现场验收待完成  
> 批准依据：用户要求按五阶段分别编写并批准规格后持续开发、测试（2026-08-22）  
> 依赖：209、210、既有 201–206 实验能力  
> 本阶段已批准，但必须在 207–210 验收后开始实施。

## 1. 目标

完成论文实验批次作为赛制版本之上批量实验的统一管理，兼容已有排表、正式比赛、训练房间和历史数据，并提供最终发布与回滚步骤。

## 2. 批次生命周期

- 状态：`DRAFT / PUBLISHED / DISABLED`。
- 批次绑定一个已发布赛制版本；发布后版本、阵容、排表、模块和关键参数冻结。
- DRAFT 且无 attempt 可改绑定版本或删除；有 attempt 不可删除。
- PUBLISHED 不回退 DRAFT；有活动/暂停比赛时不可 DISABLED。
- 正式排表固定参与者、阵营、席位和 Agent；异常正式 attempt 可重试，正常完成不可重赛。

## 3. 训练房间

- 从实验安排页面创建，赛制/名称/预设辩题预填且不可编辑，席位可自由选择。
- 可邀请任意已注册普通用户；受邀者不成为批次成员，不看正式研究数据。
- Agent 使用 209 的随机无重复补位；AI 裁判结果可见。
- 不进排行榜、正式分析、标注或问卷；完成和终止都计入配额。
- 默认每参与者最多 3 个，可在 DRAFT 调整并在发布冻结；管理员额外配额需审计。

## 4. 迁移

- 不修改历史比赛、快照、外部调用、旧 migration；旧 Agent 只读标记 LEGACY。
- 旧 URL 重定向到只读历史或新工作区；历史尝试继续绑定原配置。
- DRAFT 无 attempt 的批次允许显式迁移；迁移前后必须生成计数、引用和失败报告。
- 生产 migration 追加执行，发布前必须有备份、只读 preflight、非终态比赛为 0 和 `alembic check` 证据。

## 5. 发布顺序

1. 关闭受影响的新建入口并确认活动/暂停比赛为 0。
2. 备份源码、Web 构建产物和 PostgreSQL；不备份或输出 `.env`、密钥和临时凭据。
3. 执行追加 migration 与幂等数据迁移，运行完整校验。
4. 发布 Core/Jobs/Web，健康检查、OpenAPI、权限和历史只读检查。
5. 运行单链路和受控批次模拟；真人语音、五场长链路、11 音色盲听等未完成证据必须明确标记为待验收。
6. 观察错误、重启、活动比赛和队列指标后再开放入口。

## 6. 验收与回滚

- Core/Web/Jobs/数据库/浏览器覆盖批次状态、训练配额、邀请、正式重试、排行榜排除和历史兼容。
- 发布失败保持原版本和原入口；回滚停用新建/消费开关，保留追加 migration、快照和审计，不删除历史数据。
- 任何涉及认证、权限、状态机、计时、实时媒体协议的冲突必须停止发布并追加独立规格。
