# 213 赛制规则工作台、规则 Agent 池与资源恢复

> 版本：v2.0  
> 状态：已实现、完成验证并发布  
> 需求来源：2026-08-23 `grill-me` 逐项确认；用户随后明确批准 Spec 213  
> 依赖：200、212  
> 生产基线：Core/Jobs/API 2.0.0，数据库 `0028_connection_leases`

## 1. 目标与边界

本阶段完成三项彼此依赖的工作：

1. 从 Spec 212 清库前的受保护备份中，只恢复模型、模型 API Key 密文、音色、辩题、
   赛制规则和 AI 裁判配置；不恢复旧用户、Session、房间、比赛、实验、Agent、日志或排行榜。
2. 完全重做赛制规则管理，将平铺长表单替换为“规则目录 → 规则工作台 → 阶段配置抽屉”。
3. Agent 改为规则私有池，由全局 Agent 音色自动维护，并支持对规则阶段 Prompt 做最小化个性覆盖。

本阶段不修改 MatchActor 的阶段推进、计时起点、自由辩论举手优先、ASR/TTS/LiveKit 协议、
暂停恢复或外部调用重试语义。新建房间继续只支持 4v4；非 4v4 规则仅作历史只读。

## 2. 已确认的产品模型

### 2.1 全局资源

- 模型、音色和辩题是全局资源。
- 模型恢复包含原加密 API Key 密文；使用服务器现有加密密钥，不读取、输出或重新记录明文。
- 辩题字段为：编号、规范化辩题、正方立场、反方立场、来源、启用状态。
- 赛制可设置辩题策略：仅预设、仅自定义、预设与自定义均允许；赛制只引用全局辩题，不复制或修改辩题。
- 恢复全部备份辩题；C1–C6 按规范化文本补齐编号和来源，不生成重复记录。

### 2.2 赛制规则

一套赛制规则独立拥有：

- 规则基本信息、主持音色和默认 Agent 模型；
- 有序线性阶段、发言动作和阶段 Prompt；
- 独立 Agent 池；
- 独立 AI 裁判配置。

规则不使用草稿/发布版本工作流。各区域保存后更新当前配置，并只影响之后创建的房间。
房间创建时冻结规则、阶段、Prompt、Agent、模型、音色、生成参数和裁判配置；已创建房间、
恢复中的比赛和历史比赛永远读取自身快照，不回查当前配置。

规则可启用、停用和删除。从未被房间、比赛或实验引用的规则可物理删除；已被引用的规则只能
归档并从默认列表隐藏。规则或主持音频未通过完整性校验时不可启用。主持文本或主持音色改变后，
当前规则进入音频待生成状态，新房间暂不可使用；已有房间继续使用冻结资产。

### 2.3 规则私有 Agent 池

- Agent 唯一归属于一个赛制规则，不跨规则共享、移动或复制；不同规则允许 Agent 同名。
- 创建可用的 4v4 规则时，系统为每个启用的 `AGENT` 音色自动生成一个 Agent；主持音色不生成 Agent。
- 创建规则必须选择默认 Agent 模型；自动生成的 Agent 初始使用该模型，之后允许单独修改。
- Agent 数量由音色决定，Agent 管理不提供手工新增或删除。
- Agent 名称、头像、音色和语速只读跟随全局音色；管理员可编辑规则内启用状态、模型、生成参数和 Prompt 覆盖。
- 新增并启用 Agent 音色时，为所有可用 4v4 规则补充 Agent；修改音色基础身份时同步对应 Agent，
  但不覆盖其模型、生成参数和 Prompt 覆盖；停用/启用音色同步停用/恢复对应 Agent。
- 删除未被引用的音色时，级联删除各规则当前池中的 Agent；已有历史引用时只归档音色并移除当前池引用，
  历史房间快照继续可读。危险操作必须先展示受影响规则与 Agent 数量并二次确认。
- 恢复的非 4v4 规则为历史只读，不生成 Agent 池。

### 2.4 房间分配

- 沿用当前自由组队策略，不固定人类/Agent 比例。
- 人类在等待房间自由占据任意席位并替换该席位 Agent。
- 服务端从所选规则的启用 Agent 池随机、无重复填充剩余席位；Agent 可担任包括一辩在内的任意席位。
- 同一场比赛可以有 0–8 个 Agent；候选不足时拒绝创建/开赛并提示管理员补齐该规则 Agent 池。
- 最终阵容及全部运行配置随房间冻结。

## 3. Prompt 模型

### 3.1 继承

- Prompt 槽位归属于具体规则阶段。
- Agent 默认动态继承阶段通用 Prompt。
- Agent 只在管理员关闭“使用赛制默认 Prompt”后保存该槽位的完整文本覆盖。
- 通用模板更新后，未覆盖的 Agent 自动使用新版；已覆盖的 Agent 保持自己的文本。
- “恢复默认”删除覆盖并重新继承，不复制模板文本。

阶段槽位固定为：

| 阶段类型 | Prompt 槽位 |
| --- | --- |
| 固定发言 | 正式发言 Prompt |
| 自由辩论 | 发言意愿决策 Prompt、正式发言 Prompt |
| 准备、结束 | 无 Agent Prompt |

### 3.2 变量与目标字数

- 管理员直接编辑完整模板文本并使用 `{{VARIABLE}}`。
- 保存时拒绝未知变量和缺失的必需变量；运行前再次校验并记录使用的冻结模板。
- `{{TARGET_CHAR_COUNT}}` 由 Core 根据冻结的音色校准语速与本次可用时长计算：
  `floor(seconds × chars_per_second × 0.85)`；`max_tokens` 仍只是模型硬上限。
- 正方立论是整场首次发言，不包含“当前状态”或 `{{DEBATE_HISTORY}}`；反方立论包含正方完整记录。
- “某个 Agent 自己首次发言”不触发动态删除历史段落。

## 4. 论文实验规则

新建或规范化为一套可用的 4v4“论文实验规则”：

| 序号 | 环节 | 发言方 | 时限 | 席位 |
| --- | --- | --- | --- | --- |
| 1 | 正方立论 | 正方 | 90 秒 | 正方一辩 |
| 2 | 反方立论 | 反方 | 90 秒 | 反方一辩 |
| 3 | 自由辩论 | 双方交替，反方先开始 | 每方累计 360 秒 | 全部席位 |

自由辩论单次最多 30 秒。Agent 可担任任意席位，包括一辩；固定阶段由席位当前占用者发言。
规则绑定本规格四份 Prompt、恢复的默认 Agent 模型、独立 Agent 池和恢复的默认 AI 裁判。

## 5. AI 裁判最小配置

每套规则只配置：

- 是否启用 AI 裁判；
- 使用哪个全局模型；
- 完整裁判 Prompt；
- 结果是否进入排行榜。

不提供评分维度、权重或自由 JSON Schema 编辑器。Core 内部固定校验裁判结构化结果；管理员只编辑完整 Prompt。
关闭裁判时排行榜开关必须关闭。训练赛仍由房间/批次类型覆盖为不入榜。裁判配置随房间冻结。

## 6. 管理端信息架构

### 6.1 参考与取舍

- 借鉴 Directus/Payload 的抽屉式记录编辑，将复杂详情从列表和主流程中移出。
- 借鉴 n8n 的“选中流程节点后配置”，但不引入自由画布、分支或连线；辩论规则保持有限线性原语。
- 借鉴 Refine 的 CRUD 状态、权限和错误处理语义，但遵守 TechDesign，不引入 Refine、React Admin、
  SQLAdmin 或另一套后台运行时；继续复用现有 AdminShell、TanStack Query/Table、Drawer、Dialog 和表单组件。

参考项目：

- `directus/directus`
- `payloadcms/payload`
- `n8n-io/n8n`
- `refinedev/refine`

### 6.2 赛制规则页面

第一层“规则目录”使用服务端表格，字段仅为名称、人数、阶段数、总时长、Agent 数、音频状态、启用状态和操作。
新增、编辑、停用、归档与删除使用统一 Dialog/Drawer，不在列表内展开表单。

第二层“规则工作台”使用稳定顶部导航：

- 基本信息；
- 阶段流程；
- Agent Prompt 模板；
- AI 裁判；
- 校验与启停。

阶段流程是有序时间线。阶段卡只展示类型、名称、阵营/席位摘要、时长、Prompt 状态和错误；
拖拽手柄排序，同时提供键盘可访问的上移/下移。点击卡片打开右侧二级抽屉，抽屉页签为阶段设置、
发言动作、主持词、Agent Prompt。页面底部固定显示估算总时长、错误数量和保存状态。

Prompt 编辑器仅提供完整文本、变量插入、必需/未知变量校验、示例预览和恢复默认，不做分段表单、
可视化 Prompt 编排、测试对话或自动改写。

### 6.3 Agent 管理页面

- 页面必须先选择一个可用 4v4 规则，再加载该规则的 Agent 池；不提供“全部 Agent”混合视图。
- 页面顶部持续显示当前规则并记住管理员上次选择。
- 表格字段仅为名称、音色、模型、Prompt 状态（使用默认/已个性化）和启用状态。
- 编辑使用一个简单 Dialog，不嵌套第二个 Dialog：基础身份只读；模型下拉；启用开关；生成参数默认折叠；
  Prompt 槽位下拉；“使用赛制默认 Prompt”默认开启，关闭后显示完整文本；一个“恢复默认”按钮。
- 不提供跨规则复制、手工新增/删除、差异比较、Prompt 版本或测试对话。

所有保存失败保留输入并显示字段错误/Toast；危险操作使用确认 Dialog。目标桌面视口为 1280×720、
1440×900 和 1920×1080，不做移动端专项设计，不允许页面级横向溢出或嵌套卡片。

  Agent、模型、音色、Prompt 和裁判；正式场和训练场均消费该快照。已有仅绑定已发布赛制版本的
  批次继续按旧快照读取，不回填、不改写。
- `0038` 同时删除旧实验排表的“Agent 不得担任一辩”数据库约束；生成、导入和发布校验允许
  Agent 位于任意席位。旧 migration `0029` 保持不变，历史排表不改写。
- 新房间继续复用 `rooms.format_snapshot` 作为完整配置快照载体，但快照 schema 标记为 `rule-config-v1`，
  不要求存在或查询 `format_versions`。`rooms.format_version_id` 对新房间保持空值。
- 旧 `/api/admin/formats` 草稿/复制/发布接口从新 Web 移除并停止作为产品入口；规则工作台使用规则 API。
  旧表和旧快照读取路径仅保留兼容，不允许产生新的草稿或发布版本。
- 新表/字段表达规则阶段 Prompt、规则 Agent 池、Agent Prompt 覆盖、裁判最小配置、辩题编号/来源和冻结快照。
- 唯一性按规则隔离，例如 Agent 名称/音色约束包含 `rule_id`；同名 Agent 可存在于不同规则。
- 写事务提交后才更新缓存/Actor 或广播；创建房间在单一事务中选择不重复 Agent 并写完整冻结快照。
- 活动/暂停比赛引用的当前资源修改遵循既有引用锁；房间快照不可通过后台修改。

### 7.1 白名单恢复

使用 Spec 212 root-only 备份的 PostgreSQL custom dump，在隔离临时数据库中恢复后只读取白名单资源表。
预期源资源计数：模型 1、音色 12、辩题 10、规则 10、AI 裁判 1；旧 Agent 10 不导入。

恢复工具必须：

- 先输出仅含计数、源 ID 映射状态和冲突的 dry-run 报告；
- 事务性导入模型（含 API Key 密文）、音色、辩题、规则和裁判；
- 不读取或输出密码、API Key 明文、旧 Prompt 正文、用户字段或比赛数据；
- C1–C6 按规范化题目幂等补齐编号、立场和来源；
- 为可用 4v4 规则按启用 Agent 音色生成新 Agent 池，不导入旧 Agent；
- 非 4v4 规则标记历史只读；
- 完成后删除隔离临时数据库，保留脱敏计数与校验报告。

## 8. API 与运行时

- Core 是规则、Prompt、Agent 池、裁判、资源同步和房间快照唯一权威；Web 不拼装运行 Prompt。
- OpenAPI/Pydantic 为契约来源，Web 使用生成类型，不手写重复 DTO。
- 模板渲染使用结构化变量白名单；不得通过字符串替换绕过未知/缺失变量检查。
- 自由辩论仍为每个可用 Agent 独立并行决策，真人举手优先语义不变；Prompt 文本变化不改变选择算法。
- Agent、TTS 和裁判继续使用既有有界调度、超时、重试和过期回调丢弃规则。
- 普通运行日志不记录完整 Prompt 或密钥；完整业务请求仍只进入既有受控实验数据边界。
