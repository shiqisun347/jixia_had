## 3. 差异化Prompt方案

参考文件确定为工作区 `app(1).py`。仅AST提取IDENTITY_TEMPLATE、DEBATE_BASICS_TEMPLATE、DEBATE_TECHNIQUES_TEMPLATE、BEHAVIOR_RULES四个文本常量，不执行程序、不复制应用函数/端点/身份履历/模型/机制/时长。

共同能力底座：公平定义与判准、完整论证链、举证义务、因果与相关区分、同范围反例、有限让步后的有效比较、先回应后推进、依据真实交锋总结、简洁口语与事实诚实。拒绝偷换定义、恶意回避、虚假两难、把未回应说成承认/败北、虚构精确数据和机构研究；不得冒用院校/名人/人类履历。

每个Agent都是具备完整能力的专业辩手；差异是优先切入点与表达方式，不是能力高低或固定席位脚本。

## 4. 更准确控制生成长度

只在Prompt包和音色真实校准配置内调整。runtime的目标公式、max_tokens、正文时钟、到时行为、PCM/尾音保护保持字节相同，不用伪调低chars_per_second掩盖问题，不靠提高语速或延长阶段来读完。

1. 先分别测交换后的longwan/longhua与另三主音色，固定相同rate及模型，使用简洁论证、数字/缩写、带停顿口语、总结四类材料；保存完整生成和完整解码PCM。实际字速以完整音频测量，失败/截停样本不能冒充校准。
2. 根据真实低位可持续字速和完整音频波动拟定保守上限，固定长段预留约5–8秒收束，自由短段留出相称余量。逐Agent/逐阶段覆盖写“本段绝对上限”和现有 `{{TARGET_CHAR_COUNT}}` 同时约束，二者取小；短FREE再按 `{{MAX_SPEECH_SECONDS}}` 的窗口对照表取更小上限。动态变量来源保持现有权威值，不引入前端预算。
3. 短窗口只围绕一个命题作完整回应，长固定段最多1–2条展开充分的主论证；减少重复称呼、自我介绍、多层列点和结尾口号。按汉字/标点总量保守控制，数字尽量用适合朗读的中文，不利用字符统计漏洞。
4. 把关键结论前置，明确保留末句闭合空间；已有足够论证就自然结束，不要求凑足目标字数。不得空正文，不用未朗读草稿伪造“已讲完”，不在播放末端再裁字补救。
5. 起始上限仅为待测候选；执锋的新longwan不能沿用旧longhua数据。批准后按样本结果迭代Prompt和配置，未达到收尾门槛不发布。若模型仍不遵守预算，不借此修改核心截停或LLM适配器。

独立测试必须核对供应商真实finish_reason（stop/length）及句末闭合，不能把[SSE DONE]或COMPLETED状态直接等同完整语义。只在QA观察器采集必要枚举，不修改现有LLM适配器、不输出请求头/原始敏感响应。
