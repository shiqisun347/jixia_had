# Spec 263：音色自动同步与赛制独立 Agent 启停

版本：v2.0\
状态：已实施、完成测试与生产发布（2026-10-08）
批准依据：用户明确指示“实施，然后测试，然后上线”，已授权实现、测试与生产发布。\
需求来源：用户要求所有赛制规则自动同步已启用音色，并可针对每个赛制独立编辑 Agent 是否启用。\
依赖：200、208、213、260；本规格更新 213 中音色启停直接覆盖 Agent 状态的行为。

## 1. 问题与证据

- `CatalogService.create_voice` 仅为新建且立即启用的音色创建规则 Agent；已有停用音色重新启用不会补齐缺少的 Agent。
- `CatalogService.update_voice`、单项状态接口和批量状态操作均会把音色状态覆盖到 Agent 状态，丢失赛制内的独立停用选择。修改音色名称或语速也可能重新启用被管理员停用的 Agent。
- 当前规则 Agent API 和页面已经按精确 `rule_id` 隔离，可以复用；不需要新建全局 Agent 身份或另一套管理系统。
- 2026-10-08 生产只读盘点：16 个启用的 AGENT 音色、2 个停用的 AGENT 音色；6 套非归档、非历史只读 4v4 规则配置了默认模型，各缺少 8 个启用音色对应的 Agent。另有一套启用测试规则无默认模型且没有 Agent。
- 根目录 PRD 工作副本已被删除，本次通过 Git HEAD 读取已提交需求；不恢复或覆盖该工作区改动。PRD 的全局音色、精确规则 Agent、房间冻结边界继续适用。

## 2. 产品行为

### 音色管理

- 音色页管理全平台声音身份、头像、语速、试听/校准和全局启停；清楚区分 Agent 音色与主持音色。
- 新增并启用 AGENT 音色、重新启用已有音色、创建规则时，自动为所有可编辑 4v4 规则补齐一音色一 Agent，包括草稿、待生成音频、就绪、启用和停用规则。
- 主持音色不生成 Agent；归档规则和历史非 4v4 规则保持只读。
- 音色修改同步名称和声音身份，保留每个规则已有的 Agent ID、启停选择、模型、生成参数和 Prompt 覆盖。
- 全局停用音色使对应 Agent 不可被新房间选择，但不改写各规则的启停选择；重新启用音色后，仅恢复原本在该规则启用的 Agent。
- 音色页显示自动同步说明及受影响规则数量。既有试听、校准、引用保护和主持资产重新生成规则继续生效；不自动启用停用备用音色。

### Agent 管理

- 先选择赛制规则，展示它的音色同步 Agent 池；规则目录包含所有可编辑 4v4 规则，使用名称与状态区分同名规则。
- 每个启用的 Agent 音色对应一个规则 Agent；已有音色停用后的 Agent 保留并标记“音色已停用”，不删除个性配置。
- Agent 名称、头像、音色和语速跟随音色。列表提供“本赛制启用”独立开关；模型和 Prompt 等现有编辑保留在详情中。
- 同一个音色的 Agent 可在赛制 A 启用、在赛制 B 停用。A 的操作不修改 B，音色改名和全局启停不覆盖该选择。
- 分开显示“本赛制启用状态”与“当前可用状态”。可用性要求本赛制开关开启、音色启用、模型启用；不可用时明确说明音色停用、模型停用或赛制未配置默认模型。
- 缺默认模型的规则显示可操作的配置提示和规则设置链接；管理员选定默认模型后自动补齐 Agent，不静默替换模型或供应商。
- 新补齐的 Agent 默认在本赛制启用，继承该规则默认模型和阶段 Prompt；重复同步不覆盖已存在 Agent 的选择。
- 保存及开关失败保留原状态并显示可理解错误；切换赛制时迟到响应不得覆盖新赛制列表。

## 3. 实现与数据边界

- 复用 `agent_profiles` 的 `(rule_id, voice_profile_id)` 唯一约束和 `status` 字段。`status` 明确表示本赛制启停偏好；全局音色状态只参与有效可用性的计算，不再覆盖此字段。
- 抽取一个有界、幂等的 Core 同步服务，由音色创建/编辑/启停、批量操作、规则创建及默认模型配置调用；GET 列表不执行数据库写入。
- 用一致的事务锁顺序及唯一约束处理并发音色启用与规则创建，重复调用不生成重复记录。同步、规则配置 revision 和脱敏审计在同一事务提交。
- OpenAPI 返回全局音色状态、有效可用性及不可用原因；Web 使用生成契约，不新增手写重复 DTO。
- 检查房间分配、规则校验、实验准备/发布和管理总览的候选计算，统一采用规则开关、音色和模型同时启用的条件。既有已创建房间和已冻结实验批次继续读自己的快照。
- 兼容数据修复为显式运维动作，先 dry-run 列出缺失关系，再在批准的范围内补齐。已有 ENABLED/DISABLED 值保留为本赛制选择；历史同步已抹掉的管理员意图无法可靠恢复，不猜测重置。
- 不改写历史 migration；预计无需 schema 变更，如实现发现必须新增字段，先更新本规格并取得批准。
- 不修改比赛状态机、权限、计时、实时协议、运行时重试或真人/Agent 比例；不删除音色、规则或历史数据。

## 4. 验收

1. 启用一个已有停用 AGENT 音色后，所有符合条件且有默认模型的规则均补齐对应 Agent；重复执行无重复行。
2. 新规则获得所有已启用 AGENT 音色的 Agent；HOST 音色和历史只读规则不参与同步。
3. 赛制 A 停用某 Agent 后，改名、语速编辑、音色全局停用再启用、其他赛制编辑和重复同步均不重新启用 A；赛制 B 的独立选择保持。
4. 新房间不能选到本赛制停用、音色停用或模型停用的 Agent；旧房间、比赛、实验快照不变化。
5. 单项和批量音色启停遵守同样同步语义、引用保护、审计和事务回滚；并发创建/启用不漏同步。
6. 独立 PostgreSQL 验证生产同类缺失关系修复、稳定 ID、Prompt/模型保留及幂等性；不使用生产数据库执行测试。
7. Web 验证规则切换、独立开关、音色停用原因、无默认模型提示、错误恢复、不同赛制配置互不影响。1280×720、1440×900、1920×1080 无页面横向溢出。
8. 执行对应 Core/Web 回归、Lint、类型、OpenAPI 契约、专项浏览器和仓库 `pnpm build`；失败如实记录，不将未执行的生产验收标为通过。

## 5. 发布与回滚

- 先完成实现、独立库修复演练与测试，准备可审查的制品和修复清单；本次规格批准允许实施与测试，线上发布另按用户明确发布指令执行。
- 发布前保留数据库和应用恢复点，检查非终态比赛、单一模型缺失规则和数据修复预览；修复不擅自给无默认模型的测试规则选择模型。
- 回滚恢复本次变更的 Core/Web 制品，保留历史数据和审计，不执行 migration downgrade。新增 Agent 保留，必要时逐条恢复本次变更前状态；不能通过删除历史引用记录回滚。
- 旧代码会重新覆盖赛制启停偏好，回滚期间冻结音色启停/编辑入口，直至恢复安全同步代码；既有比赛继续读取快照。

## 6. 实施与验收证据（2026-10-08）

- 新增 Core `rules/agent_pool.py`：同一事务内用固定 PostgreSQL advisory lock 串行化规则/音色同步，复用规则音色唯一约束；新建规则、默认模型配置、音色创建/编辑/单项启停/批量启停调用同一同步服务。
