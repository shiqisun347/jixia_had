# 209 赛制工作区与版本化 Agent/Prompt

> 版本：v2.1  
> 状态：实现与独立 PostgreSQL 门禁完成；未部署  
> 批准依据：用户要求按五阶段分别编写并批准规格后持续开发、测试（2026-08-22）  
> 依赖：200、207、208；必须先解决根 PRD 的全局 Agent 与稳定补位旧表述  
> 本阶段实现与数据库集成门禁均已完成，线上发布不在本轮授权范围内。

## 1. 目标

实现赛制中心：赛制版本、结构化规则、赛制模块、版本专属 Agent、Prompt、AI 裁判和辩题引用。发布形成不可变运行快照，历史比赛继续读取旧配置。

## 2. 版本生命周期

- `format_key` 稳定不变；每个赛制最多一个草稿、一个当前发布版本和多个历史只读版本。
- 草稿由当前发布版本深复制；Agent 行、Prompt 行、模块配置和 AI 裁判配置均独立复制。
- 已发布版本不可编辑、不可重新激活；恢复只能复制为新草稿。
- 发布需变更说明、完整校验、主持音频 READY、Prompt 变量/模型/音色/模块依赖校验，并在一个事务中冻结快照。
- 乐观锁保护并发编辑；旧比赛只使用启动时快照。

## 3. 规则与模块

- 规则编辑器只支持代码注册的线性阶段；`END` 固定最后，禁止原始 JSON。
- 修改主持文本/音色会使主持音频失效；未试听确认不得发布。
- 模块包括普通房间、批次/排表、固定席位、训练房间、参与者标注、专家标注、问卷、AI 裁判、排行榜和研究导出。
- 删除阶段必须解决孤立 Prompt；模块冲突或缺失依赖阻止发布。

## 4. Agent 与席位

- Agent 只属于一个精确的 `format_version_id`，复制时创建新 ID，不软连接。
- Agent 引用全局模型/音色，参数覆盖受模型 Schema 限制；发布冻结解析后的模型、音色、参数、头像和 Prompt。
- 同版本 Agent 与主持人音色不得重复；停用全局模型/音色不得破坏已发布快照。
- 普通房间从当前赛制版本合格 Agent 中随机、无重复补位；不足时 Core 拒绝开始并提示管理员配置数量。
- 正式排表指定 Agent/席位时覆盖随机补位；用户不能在普通房间选择 Agent。

## 5. Prompt

- 槽位由 `stage + purpose` 代码注册，例如自由辩论决策和发言生成。
- 赛制默认模板可被每个 Agent 用完整模板覆盖；管理员直接编辑全文。
- 变量为代码白名单，未知或缺失必填变量阻止发布和运行调用；不使用空字符串兜底。
- 输出契约选择代码支持的契约；真实测试标记 `ADMIN_PROMPT_TEST`，不进入比赛状态/历史。

## 6. AI 裁判与辩题

- 每版本初期一个 AI 裁判配置，绑定全局模型，冻结 Prompt、参数、维度和输出契约。
- 全局辩题只能引用；版本、批次和房间可创建私有不可变快照。

## 7. 迁移与冲突解决

- 现有全局 Agent 迁移为 `LEGACY` 只读；不得重写历史比赛。
- 当前 PRD 中“全局 Agent 可编辑”和“稳定顺序补位”必须在实现前修订为本规格规则，并在变更记录中保留兼容说明。
- 迁移脚本只能新增表/列/索引，提供幂等 preflight；失败不切换当前发布版本。

## 8. 验收与回滚

- Core 覆盖草稿复制、乐观锁、发布全量校验、快照隔离、Agent 数量不足、随机无重复和历史读取。
- Web 覆盖赛制工作区、规则时间线、Prompt 变量校验、模型测试、版本状态和发布确认。
- 发布失败保留原版本；回滚通过关闭新版本创建/消费入口，不删除已生成快照或历史数据。
