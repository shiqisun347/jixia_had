# Spec 288：标注响应与音频授权查询的二级载荷护栏

状态：本地实现完成，待受保护发布

## 问题

Spec 285 已限制任务数量，但单个任务可以包含任意数量的标注项目、答案和冻结 JSON。
因此分页不能单独保证响应、Core RSS 或专家音频授权查询有界；Web 自动追页也可能因服务端
重复游标无限请求。

## 范围与验收

- 参与者/专家任务响应对每个任务分别限制 512 个关联项目、2,048 个答案和 8 MiB
  逻辑 UTF-8 JSON/文字载荷，单次页面总载荷最多 64 MiB；数据库先以
  `count`/`octet_length(jsonb::text)` 聚合预检，再读取 JSONB、文本和关联行。超限使用
  脱敏、稳定的 `experiment_annotation_payload_too_large`（HTTP 413）错误并停止构建响应。
- 标注列表默认 25 条、最多 50 条；专家音频授权查询最多读取 4,096 个答案和 64 MiB
  逻辑 UTF-8 JSON，先做聚合预检，避免把整项历史无限加载进 Core。
- Web 任务分页每页请求 25 条，最多自动读取 4 页；重复或超过上限的游标以可操作错误结束，
  不进入无限循环或无界累积。正常 v2.0 实验批次（18 场正式赛）在上限内保持数组兼容。
- 赛后物料化的 Core/Jobs 读取在完整 JSON 查询前先做行数、文本和 JSON 字节聚合预检；
  预检失败不会把异常 payload 载入 Python。
- 正常正式 4v4 字段和响应保持不变；不截断、不静默丢弃历史数据，不涉及 migration。

## 回滚边界

仅回滚 Core/Jobs/Web 应用代码与测试即可恢复旧查询行为，不删除数据库数据；阈值调整需另立
规格并用代表性大比赛校准。未修改 migration，未截断或静默丢弃历史标注数据。

## 验证证据

- Core 标注单元测试覆盖 child sentinel、逻辑 UTF-8 字节预算和响应预算；实验集成测试在
  独立 PostgreSQL 通过（`1 passed`）。
- Web `experiments-api` 测试覆盖 25 条请求、重复游标和四页上限；相关 Web 全套通过。
- Ruff、Pyright 和 Prettier 对变更文件通过；未进行生产写入、重启或发布。
