# Spec 289：赛后音频回放取消清理、快照逻辑大小与源路径边界

状态：本地实现完成，待受保护发布

## 背景

Spec 287 已为赛后回放增加行数、文件大小和 ffmpeg 输出上限。复审发现两个边界
仍然可能破坏 Jobs 稳定性：JSONB 的 `pg_column_size` 只反映 PostgreSQL 物理
存储大小，压缩后的超大快照仍可能在 Python 解码时膨胀；取消回放任务时如果
没有回收 ffmpeg 子进程，旧进程会继续占用 CPU、文件描述符和临时文件。数据库中
异常或被篡改的音频路径也不应让 Jobs 读取配置存储根之外的文件。

## 范围与验收

- 运行时快照在传输完整 JSONB 前使用 PostgreSQL `octet_length(runtime_snapshot::text)`
  检查 UTF-8 逻辑字节数；压缩物理大小不能绕过 4 MiB 上限。
- `_run_ffmpeg` 使用无管道标准错误输出；超时和 `CancelledError` 都杀死并等待回收
  子进程，保留原取消语义。回收失败不吞掉原任务取消。
- 主持音频和辩手/Agent 音频路径必须解析到对应配置的可信存储根内，并拒绝路径穿越、
  根外绝对路径、符号链接逃逸和过长路径；根内缺失文件仍按历史逻辑跳过。
- 规则验证允许的单场估算上限为 90 分钟。人类 PCM 为 16 kHz、16-bit、单声道，
  90 分钟原始输入约 172.8 MB；回放输入预算提升至 256 MiB，为 Agent/主持 Ogg
  和文件系统误差保留余量。单文件 16 MiB、源数量 1,024 和输出 64 MiB 上限保持不变。
  该预算保护 Jobs/ffmpeg，不截断业务音频；超过时稳定失败并可重试或人工处理。
- 正常正式 4v4 的回放顺序、文件缺失跳过、READY/FAILED 闭环和任务租约保持不变；
  不修改数据库 schema 或既有 migration。

## 回滚边界

仅回滚 Jobs 音频 worker、CLI 调用、测试和本规格即可恢复 Spec 287 的旧行为；不涉及
生产数据库写入、数据删除或外部服务重启。发布前后观察 `POSTMATCH_AUDIO` 错误码、
Jobs RSS/文件描述符、ffmpeg 残留进程、临时磁盘和回放时延。

## 验证证据

- 单元测试覆盖压缩 JSONB 的逻辑字节 SQL、取消/超时子进程回收、路径穿越/符号链接
  逃逸和 90 分钟原始 PCM 预算。
- Ruff、Pyright 和 Jobs 音频专项测试通过；真实长规则回放与受保护生产窗口观察仍需
  独立执行，不能由合成测试替代。
