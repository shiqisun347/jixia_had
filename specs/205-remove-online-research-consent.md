# v2.0 移除线上研究同意环节

> 状态：已完成  
> 日期：2026-08-22  
> 依据：用户明确要求完整去除平台内研究同意书和伦理批准环节

## 1. 范围

- 管理员创建实验批次时不再填写研究同意书版本、摘要或全文。
- 参与者预约页不再展示研究同意书、同意按钮、同意状态或相关提示。
- 进入实验房间不再查询或校验 `experiment_consents`。
- 当前 OpenAPI 契约移除研究同意接口、响应模型和预约的 `consent_required` 字段。
- 平台注册条款和真人参赛条款不在本规格范围内，保持现状。

## 2. 兼容边界

- 不修改既有 migration，不删除 `experiment_consents` 或 `experiment_batches` 的历史列。
- 新建批次由 Core 为历史非空列写内部兼容值；该值不对 API 和 UI 暴露。
- 已有历史批次和同意记录保留，但不再参与当前实验流程。
- 不增加“线下签署”“已签署”或类似替代状态，平台不记录或推断平台外流程。

## 3. 验收标准

- 不提供同意书字段即可创建实验批次。
- 预约响应不含 `consent_required`，参与者可直接点击“进入固定房间”。
- 没有 `experiment_consents` 记录的固定席位用户可正常进入预约房间。
- 管理端、参与者端和当前操作手册中不存在研究同意、伦理批准或“线下签署”等替代提示与操作。
- 现有平台注册与真人参赛条款测试继续通过。

## 4. 回滚边界

- 回滚应用代码即可恢复旧入口；历史数据库结构和记录不变。
- 不通过删除表、列或历史记录完成回滚。

## 5. 验证证据

- 完整 `pnpm check` 通过：格式、Lint、类型、工具 47、QA 5、Web 172、Core 243、
  Jobs 23、OpenAPI 契约及 29 页面生产构建。
- Playwright `desktop-1440x900` 专项 2/2 通过，覆盖管理员无相关字段、参与者无相关 UI
  且直接进入固定房间。
- 数据库集成用例已更新为无相关字段创建批次；本次本地会话未配置独立
  `TEST_DATABASE_URL`，因此未重跑数据库集成。
