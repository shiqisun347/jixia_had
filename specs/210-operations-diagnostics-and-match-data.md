# 210 比赛数据、运行日志与诊断

> 版本：v2.1  
> 状态：实现与独立 PostgreSQL 门禁完成；未部署  
> 批准依据：用户要求按五阶段分别编写并批准规格后持续开发、测试（2026-08-22）  
> 依赖：207、208、209；TechDesign 的 Core 权威与有界队列约束  
> 本阶段已批准，但必须在前置阶段验收后开始实施。

## 1. 目标

将比赛事实浏览、运行日志、事故、后台任务和审计日志分成职责清晰的后台页面，并在全局、赛制、批次和单场比赛上下文复用查询组件。

## 2. 比赛数据浏览器

- 统一列表按赛制、版本、批次、状态、时间、参与者和比赛 ID 查询。
- 详情按需加载比赛事实、状态事件、发言、外部调用摘要、裁判结果和任务；原始 Prompt/响应/ASR 按 ID 加载。
- 不复制历史数据；管理员可导出授权数据，敏感字段遵守现有脱敏规则。

## 3. 运行日志

- 新增持久化 RuntimeLog 查询页，字段含时间、级别、服务、赛制、版本、比赛、请求/追踪 ID、消息和脱敏结构化上下文。
- 级别 `INFO/WARNING/ERROR/CRITICAL` 默认持久化；DEBUG 为短期显式开关。
- 默认保留 30 天，清理不影响比赛事实、审计、外部调用摘要和研究数据。
- 自动刷新：关闭/2s/5s/10s/30s/1m；仅相对时间截止当前可用。
- 标签页隐藏暂停，恢复立即刷新；请求互斥；新行不插入阅读位置，显示“有 N 条新日志”。
- URL 保存查询条件、时间和排序，不保存刷新开关。
- 有界队列和丢弃计数可见；禁止输出密钥、Cookie、Authorization、密码、私钥、完整音频和供应商原始响应。

## 4. 事故、后台任务、审计

- 事故聚合影响比赛、日志、任务和处理状态，不等同日志行。
- 后台任务展示状态、进度、重试、错误摘要和关联资源；重试遵守幂等和取消语义。
- 审计日志独立导航，记录操作者、资源、动作、脱敏前后摘要、结果和请求 ID；敏感详情查看本身也审计。

## 5. 实时与安全边界

- Core 是日志和比赛查询的权威；Web 不推进计时或状态。
- 日志消费分页/游标有界；禁止无条件全量加载。
- 过滤、详情和导出均再次执行管理员权限与资源范围校验。

## 6. 验收与回滚

- Core 测试覆盖保留清理、级别、脱敏、队列丢弃、查询过滤、游标和权限。
- Web/浏览器覆盖自动刷新、隐藏标签页、互斥请求、新日志提示、事故/任务/审计分离及三个桌面视口。
- 若新日志管道异常，关闭 RuntimeLog 写入/入口并继续使用现有诊断读取；不得删除旧日志或比赛数据。
