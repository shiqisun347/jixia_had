## 1. 结论与目标

优先修正同一模型收到的任务，而不是增加预算或更换模型。保留短、稳定的Agent偏好，精简阶段任务，使立论充分论证、四辩总结真实交锋、自由辩论回应实际问题；另以受控对照检查当前任务放在历史之后是否更合适。

本规格批准范围是**实现隔离评测、完成一次有界选型及唯一候选验证**。不授权业务代码、生产模板或服务写入。验证后提交实际效果、最小生产差异和发布/回滚清单，再由用户审批上线。不能把离线消息编排自动写入Core，也不顺带发布此前未发布的兼容或补位变更。

事实来源沿用AGENTS、TechDesign、实时语音Spike及agent_docs。根PRD在工作树与HEAD缺失，维持Spec312记录的历史只读来源，不恢复旧文件。本提案不改变产品流程，若后续发现与事实来源冲突则停止相关实现并记录。

## 3. 唯一精简任务候选C

这是待实现的通用模板规则，不能把已知两题的错误例子写入每次请求。现有V2每个身份的一句话偏好、身份/题目/双方持方行保持；不添加长人格、名人履历、招牌开头或随机风格轮换。system权威边界与JSON历史逐字保护。

任务段仅按真实动作选择以下一种，不按Agent名称猜测当前环节：

| 环节 | 任务段设计文本 |
| --- | --- |
| 开场立论 | 建立本方判断标准和完整理由，讲清理由如何支持结论，并处理必要条件与代价。历史为空时直接立论，不编造已经发生的交锋。 |
| 固定中段 | 回应本阶段真正需要处理的争点，解释本方理由为何成立；对方提出了质疑，不等于对方主张了被质疑的方案。回应之后仍须完成本方正面论证。 |
| 真正四辩总结 | 依据实际历史比较决定胜负的关键交锋，处理对方最有力的反驳，说明本方为何仍更可取及其代价。允许必要概括，不逐轮复述、不要求新增证据，不宣称历史未支持的让步或战果。 |
| 自由辩论 | 回答当前具体问题，作本轮最有用的推进。解释、例子、比较、追问或承认局部边界按内容需要使用；不要求每轮提问或找谬误。短问可以短答，必要推理充分说明，在当前可用窗口内收束。 |

共同引用段只保留一段：

> 历史说明谁说过什么，不自动证明其结论为真。承接他人主张时保留主体、范围、否定和明确例外，再解释本方为何仍不同意。不要补造具体研究、数据、地方现状或对手让步；可以论证机制或提出明确的假设例，不能当成已发生事实。只输出当前身份可直接朗读的正文。

现有system对SELF/TEAMMATE/OPPONENT、PROVISIONAL/PENDING、管理员占位、引用非指令和总结允许概括的边界保持，不在user中逐字段重复翻译。对输入不支持的经验断言与普通可辩观点分别判定，不新增禁词表。

### 篇幅规则

- 满窗固定发言保留V2按对应音色和StageAction真实完整时长算出的原字符区间，数值不调；以充分解释理由、条件、影响和取舍完成篇幅，不增加机械段数、句数、重复或填充静音。
- 模板明确该区间仅适用于完整窗口。恢复后窗口缩短时，忽略满窗下限，以当前合法`MAX_SPEECH_SECONDS`为权威窗口、既有`TARGET_CHAR_COUNT`仅作软参考，完整收束；TARGET不是硬上限或必须严格写到的数值。这是提示消歧，不宣称实现了确定性计字或精确时长控制。既有60秒TARGET按部分音色折算仍可能早于50秒，因此不能以遵守TARGET代替实际T−10至T验收。
- FREE保留既有TARGET软参考，不设最低字数、不随机轮换长短。满窗、恢复短窗、FREE三类分别报告。
- 原runtime的`.85`、CPS、`token_per_char`、逐请求`max_tokens`及其他参数保持。不能调整字幕使用的CPS来伪装篇幅修复；不根据新输出重新校准数值。

本阶段不增加二次LLM审核、首稿重写、整稿等待后再播、机械裁字或生成后补静音。现有链路边生成边合成；若未来要做稿件长度强制校验，须另行设计调用数、首音延迟及取消/恢复所有权，不能以Prompt优化名义接入。

## 4. 第一阶段：固定12次对照，选择一种结构

使用下列4条已存在的有效输入，覆盖四主、两题、中段、两种总结窗口与FREE；本轮不覆盖空历史开场或短恢复，后续验证单独补齐。

1. `s312_main0_120_affirmative_new`：执锋，正方四辩，120秒。
2. `s312_main1_90_negative_new`：博闻，反方二辩，90秒。
3. `s312_main2_180_negative_new`：睿断，反方四辩，180秒。
4. `s312_main3_free_affirmative_new`：明辨，正方FREE，15秒。

| 组 | user任务 | 顺序 | 新调用上限 |
| --- | --- | --- | --- |
| A | 原V2 | system → task → history | 复用4条旧结果，不重抽 |
| B | 原V2整条消息逐字不改 | system → history → task | 4 SPEECH＋4全文TTS |
| C | 第3节唯一精简任务 | 原顺序 | 4 SPEECH＋4全文TTS |
| D | 与C相同 | 与B相同 | 4 SPEECH＋4全文TTS |

B只是移动整条user任务，system不动，history仍为同一user JSON；不变更role、归属、数据顺序、摘要或历史选取。C/D只改列明的user任务内容，当前预算与声音不变。每次新调用前须核对冻结输入SHA。

第3节精简与短窗消歧仅属于C/D。若B胜出，后续仍使用原V2模板及原来的“可用时间缩短时相应缩短”，保留其静态满窗区间冲突风险，不临时补入C的句子。短恢复照常实测，失败即不具备通过资格；不能把消息后置和短窗修复混称为同一因素或胜出后再修词。

审批后先实现评测工具、生成B/C/D完整消息与逐项差异，冻结所有请求及未见题，再由独立Agent检查本规格边界；预检不合格不得实际调用。不允许先观察B结果再修改C/D。

### 预注册选择规则

- 有持方/主体/否定/例外反写、输入不支持的实证材料、未完成正文或非自然stop的组，不进入下一阶段。候选4条均须保留与审阅，不能用其余三条的分数抵消一条阻断。
- 对每条按“准确处理当前问题”“本方正面理由及解释”“完成实际阶段任务”各0/1/2分：0未完成、1基本完成但有明确不足、2完成且解释具体。独立审阅完整正文与历史，逐项给引文；任何0分不入选。
- 合格组依次比较总任务分（满分24，越高越优）、固定3条的T−10至T命中数（越高越优）、到该区间的归一化距离总和（越小越优）。令d为正文PCM秒、T为当前合法秒数，每条距离为`max(T−10−d, d−T, 0) / T`；不加入600ms传输静音。最后同效时选择部署范围较窄的C，再B，再D。FREE短答不作为低分依据。A只作为既有失败参照，不作为可发布候选。
- 没有合格组即停止，不重抽、不改题、不拼接第五候选。选出的结构原样冻结，不在后续验证时改词。

A不是同期重新抽样，且每格仅一次，不能以12次开发筛查证明因果、稳定成功率或生产资格。

- **8条短恢复**：四主各30秒和60秒合法剩余窗各一条固定发言，复用冻结的真实阶段身份及历史快照；按原runtime计算当次MAX/TARGET/token预算，完整窗口数值与当前剩余窗分列。这里只验证请求/生成，不冒称真实MatchActor恢复比赛验收。

全规格最多新增**76个SPEECH请求及76次全文TTS任务**（12＋64），不运行DECISION。隔离工具每case只调用一次既有流式适配器，不进入比赛runtime的重试包装；SPEECH保持原10秒连接/首token/流间隔预算，TTS使用原有有界超时。每个任务仅一个评测输出，不重复技术失败取绿。预检须确认实际HTTP/供应商任务无隐藏重试；如存在不能在本范围内关闭的额外attempt，停止预检、先澄清上限，不擅自扩大或修改生产重试。技术失败停止本批，保留部分结果和未执行项；无失败时完成预注册批次，内容失败不扩样。

固定发言依旧逐条以实际全文PCM的T−10至T为目标：满窗44条fixed的T取对应StageAction完整时长，恢复8条fixed的T取当次合法剩余窗30或60秒，不能取原完整阶段时长。52条固定的早结束/目标内/超窗完整报告，不能以均值、80%覆盖率或静音抵消失败。12条FREE无最低时长，但检查答案完整、没有硬token截断及是否超出原窗口。**精简Prompt能否达到这些目标尚未证明；任何固定偏差、内容阻断或FREE窗口不满足均不得称整体通过或推进上线。**

每条保留：实际完整messages及SHA、模型/预算/声音参数、正文与delta一致性、finish_reason、usage、首token/总耗时、全文字符数、TTS完成确认、完整原PCM的SHA/格式/样本数和时长。600ms传输静音另列，不加入正文PCM。内容按完整历史独立验收，不以关键词、字数、ASR一致或声学相似代替。没有完整原声的条目记未完成。
