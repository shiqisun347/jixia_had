# Spec317 — 固定发言长度冲突的最小修正

- 版本：v2.0
- 日期：2026-10-18（Asia/Shanghai）
- 状态：已完成批准的14组有限验证，候选未通过、未上线。12候选7时长合格/5超时/0偏短，2确定内容错误；线上旧配置保持。
- 用户目标：固定阶段真实发言达到允许时长的75%～100%，重点四辩；采用最简单有效的方式，不改当前比赛核心流程。

## 1. 问题依据

Spec315真实YXH冻结资料中，博闻/明辨四辩模板仍是已发布v11：要求“三个短自然段，各一句、每句最多六十字，总共最多一百八十字”，后文再次要求“正文绝对上限180字”“完成即结束，不凑上限”。同一120秒窗口已有TARGET485/488、max_tokens501/504。二辩90秒也有240字/四句话上限，早段另有其他硬编码长度。模板内相互矛盾的长度规范会压短正常固定发言，不能仅靠提高token上限修正。

只读审计见`profile_output/spec317-design/FIXED_LENGTH_ACTUAL_BASELINE_AUDIT.md`；旧16四辩模板键/SHA与Spec312保护快照一致，旧输出仅87～162字符，但旧批没有TTS，不把估算秒数写成实测。Spec315仅为该YXH的130模板导出，不冒称已审全线上670。

Spec314 D未上线。本规格不采用其整套候选，也不改它原来的失败记录。新75%～100%仅是本规格的用户目标，不追溯覆盖旧T−10到T资格。

## 2. 唯一改动：固定SPEECH模板长度文字

执行时只读核对当前启用的正式4v4赛制，以权威`stage_kind=FIXED_SPEECH`及`purpose=SPEECH`选中其现有默认模板和Agent覆盖。冻结精确主键、旧/新正文与SHA；未满足该类型或内容与预期不符的项停止核对，不按“包含180”等字符串泛选，更不替换整套585/670模板。

在这些固定模板内：

1. `字数上限：{{TARGET_CHAR_COUNT}}`改为`目标字数：{{TARGET_CHAR_COUNT}}`；默认固定模板的“正文控制在TARGET字以内”也以唯一目标长度段替换，避免残留第二条相反指令。
2. 删除额外硬编码字数帽、每秒二次折扣/额外预留秒数，以及“完成即结束、不凑上限”等鼓励提前收束的长度指令。不同阶段的180、240、280、320等常数一并按其旧长度段处理，不只删一个180而留下第二处。
3. 取消“最多四句”及四辩“三段各一句/每句60字/总180字”的篇幅限制。四辩原“第一句/第二句/第三句”改为“先/再/最后”的论述顺序，保留原方案比较、已有事实、持方、结论等实质任务；允许每部分充分解释。
4. 每条固定模板只保留一处长度指导，拟定完整文字：

> 正文以 {{TARGET_CHAR_COUNT}} 字左右为目标，允许上下浮动约一成。充分解释理由、回应本场争点并自然收束；不只写简短结论，也不重复凑字。只输出可朗读正文。

已有`TARGET≈T×CPS×0.85`保持。目标上下约10%在线性校准估算下约对应76.5%～93.5%T，落于用户允许区间，保留自然停顿余量。这是生成引导，不是音频保证，最终以真实PCM测量。

## 3. 明确保留

模型及其参数、音色/rate/CPS、0.85系数、token计算/max_tokens全部保持。当前身份/人格/持方、完整历史与消息顺序保持，仅移除上述篇幅冲突，不新增知识或事实。

FREE SPEECH、DECISION、裁判、主持及其他非固定模板逐SHA保持。Core/Actor、ASR/TTS协议、流式边生成边合成、计时起点、到时截断、暂停恢复、generation/epoch及失败重试语义都不改；不添加二次LLM改稿、自动续写、播前整稿门禁、静音凑时或降速凑时。不顺带发布Spec312未上线Core及585新模板，不修改本地既有业务工作区。

## 4. 有限验证（最多14次LLM＋14次全文TTS）

只验证这一个候选；先固定完整输入、旧/新模板、声音、参数、顺序和全部case。串行离线调用，无比赛写入或并发压测；复用既有受控凭据与脱敏QA工具，不读api.md/.env、不把密钥落盘。

- 旧线上基线2条：博闻、明辨各一条120秒四辩，使用同一套与对应候选匹配的完整历史。
- 候选四辩8条：博闻/明辨×两套不同完整历史×两次独立生成，T=120秒。覆盖反复生成的波动，不用单次筛查承诺稳定。
- 候选其他固定2条：执锋、睿断各一条90秒二辩。
- 候选短剩余窗2条：博闻30秒、明辨60秒各一条，以实际本次窗口和既有动态TARGET渲染；不拿满窗字数灌入短窗。这里只覆盖两个短窗，不声称覆盖所有恢复组合。

每条一次；核对实际HTTP请求、TTS连接和run-task数，禁用离线工具的隐藏重试，保证14＋14上限。技术错误保留记录并停批，内容/时长不合格也保留，不换词或重抽追绿。未用完调用不自动增加case。

候选12条须逐条满足：

- 全文TTS实际可朗读PCM时长d，严格`.75*T ≤ d ≤ T`。120秒=90～120秒，90秒=67.5～90秒；不计额外600ms传输静音、LLM等待或人为停顿。
- LLM自然stop、末句完整；不能把被到时强制截断后的播放时长当作全文达标。报告字符数、tokens及音频秒数，互不替代。
- 保持本方立场和真实来源，没有新增重大事实/归属错误，无明显循环复述凑字。按完整历史审阅，不用“时长够了”掩盖内容失败。

12条中任一不合格，报告失败、保持线上原配置，不自动扩为多候选大评测。旧基线仅供对照，不要求其满足新目标，也不冒称小样本已证明全概率保证。

配置选择/旧SHA/变量合法性/仅长度段差异及FREE等保护用纯检查验证。此次没有业务代码改动，不为此重跑全部产品、真人语音或五场压力。

## 5. 配置上线与回滚

批准范围含验证通过后的这一份固定模板配置更新，不含其他业务部署。上线前再核当前启用规则、模板SHA、服务与比赛活动，变化则停止合并差异；不终止比赛或重启服务。

备份每条旧文本/变量及配置修订；复用原有模板校验、必要修订及管理员审计语义，在有界事务中按主键/旧SHA精确更新本次清单，失败整批回滚。不改schema、音色校准、主持资产或模型。安装后核固定差异、未改项哈希、新建房间冻结配置及服务健康；不会为了配置更新安装其他Core/Web文件。核验不符则按所保存文本恢复并形成正常新修订，不删除历史。

规则修改只影响之后新建房间；已冻结房间/比赛保持原配置，不回填旧比赛。候选通过后如需验证新房间冻结，仅建明确标注的自有QA房间并正常关闭，不声称完成整场真实媒体或扬声器验收。

完成后更新本规格、specs/README、MEMORY及本轮实际报告。保留Spec312/314已知尾音/内容风险；本次只解决固定长度冲突。

设计独审：`profile_output/spec317-design/SPEC317_REVIEW.md`，无明确阻断。默认固定模板残留上限和供应商实际调用记账两项提醒已纳入执行预检；尚未实施或调用。
