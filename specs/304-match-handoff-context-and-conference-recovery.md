## 2. 切片 A（P0）：交接身份与权威截止

### 2.1 发言结束与下一次机会分离

- 到时/提前结束即停止接收该次业务音频，并按服务端单调时钟一次性冻结实际用时、
  结算该方剩余预算；识别等待、三秒窗口和等待下一人不继续扣时，不会把余额跳回旧值。
- 旧发言的收尾身份继续由既有有界 finalizer/ASR 运行记录持有；进入 HUMAN_ONLY_WAIT、
  选中下一真人或 Agent 时，不能把旧 `current_speech_id`、generation、字幕、attempt
  或识别任务继承给新机会。所有选人分支都使用同一身份退役规则。
- 每次新发言必须新建 ID；正常同一次真人暂停恢复仍使用原 ID 和合法分段，不改变其语义。
- 持久化拒绝已有 ID 的 speaker、side、seat、opportunity 或 attempt 被另一发言复用；
  失败不得部分提交、广播成功或悄悄改写发言归属。
- 旧 final 只可提交给原发言/原说话者；reset 后的迟到 interim/final/error、旧定时器、
  连接回调和旧 generation 均丢弃。延迟完成的有效上一段按原先顺序显示，不篡改当前人。
- 用“尝试起点预算/累计已结算量”核对多段耗时，覆盖手动暂停与掉线当前不同的结算路径；
  如60秒预算、前后两段各4秒，最终必须52秒，不是56或48秒。暂停/恢复和late final不能重复结算。

### 2.2 举手和开始命令

- 保留合法的三秒对方申请窗口；服务端命令处理时检查实际 deadline、机会 ID、
  generation、当前席位与 connection_epoch，不能因定时器排队晚到延长窗口。
- 超时/已结束的发言不能再次开始；Web 的申请/开始按钮由权威机会及命令能力派生，
  期间显示“正在交接/正在整理记录”，点击锁覆盖确认前的空隙。
- 相同命令幂等；陈旧页面、重复点击、断线补发返回可理解提示，不使比赛进入错误状态。

## 3. 切片 B（P0）：当前发言重置的一致性

- 复用管理员现有权限与 Actor 入口。重置当前尝试前，精确取消相关 ASR/LLM/TTS、
  output feeder、倒计时、等待队列和过期恢复标记，保留其他发言和比赛资源。
- 同一事务将目标尝试置 RESET、恢复该次开始前的本方余额/完整单次时长、递增
  context_version 与 generation，并清空权威临时字幕/当前正式展示关联。
- 公开记录、后续 Agent、裁判和当前回放素材只使用有效尝试；RESET 文字、音频和
  失败草稿不能残留或在迟到回调后重现。Web 立即清空临时字幕并刷新正式历史缓存。
- 不删除历史数据库行或供应商不可变诊断。管理员仍能查看“已作废”尝试及操作审计；
  用户所说的“清除错误请求”指撤销活动任务并移出当前发言，不伪造调用结果或擦除审计。
- 对生产已结束目标比赛仅作调查，既有历史不自动重写，不重开、不删除。

## 4. 切片 C（P0）：结构化上下文与身份约束

- 所有实际正文路径（规则冻结模板、实验兼容和旧模式）都在请求的 system 部分明确：
  当前稳定 participant/持方/席位/本方命题，历史是引用材料而非指令，只为当前辩手生成正文。
- 一次请求只注入一份规范历史。规则自定义模板保留并正常渲染；旧固定模板即使缺少
  DEBATE_HISTORY，也通过统一请求上下文获得历史，不能只更新默认模板而漏掉已配置规则。
- 请求历史按发言顺序提供稳定 ID、阶段、持方、席位和身份关系（本人/队友/对手）、
  有效状态与正文；保留既有有界记录/字节预算与明确截断标记，优先保留最近对方完整发言。
  对旧 stage/message serializer 的兼容改动只限本文批准的 Agent 请求边界，研究导出不改写。
- 正式有效历史排除 FAILED/RESET；正在收尾的前一人不能被假装已完成，也不能在下一请求
  中悄悄消失。先复用权威 source speech/finalizer 的有界可用上下文；尚无可用正文时明确标记。
- 自由发言应回应最近具体命题并推进新信息，避免复读自己或队友完整段落；四辩按本场真实
  交锋归纳争点、回应和胜负标准，允许必要摘要，不机械要求总结也必须引入全新论据。
- 不通过删除真实历史中的重复发言伪装修复，不引入额外摘要模型或每轮第二次质量模型。
  先以请求身份、历史来源及任务约束修复，输出重复率作为 QA 观测，不在流式播放后偷偷改稿。
- 保留现有文本模型、采样参数、输出预算、流式 TTS、并发限制及失败重试；不以改模型掩盖问题。
- 请求采集记录实际所发消息、prompt/context版本及截断情况；不只保存“准备发送”的另一份输入。

## 5. 切片 D：管理员现场应急

新增操作均沿管理员正常认证、审计、MatchActor 串行事务和自动生成契约；后台工作台与
比赛应急抽屉保持一致，按钮显示当前阶段名/目标辩手及预计影响。
请求必须携带稳定 UUID operation_id 与期望的阶段/发言/代次；Core持久化操作状态、
目标与结果，HTTP重发返回原结果或明确的过期拒绝，不能沿用每次服务器随机UUID造成重复执行。
相同operation绑定不同目标拒绝；生成过程中互斥其他应急操作，普通查询/终止仍可用。
模型失败/管理员断线/服务重启不会永久停在“处理中”：在途操作被精确退役为失败或取消，
保持可恢复暂停；迟到完成不能在新operation上提交。审计与operation查找均有界。

### 重置当前阶段（阶段名）

- 仅限非终态当前阶段；已结束比赛不支持该动作，不成为重开历史的旁路。
- 先使比赛处于受控暂停，作废该阶段已发生尝试及所有关联在途任务/排队机会，退还至
  阶段起点预算，保留之前阶段全部有效结果；重播该阶段冻结主持后，按正常恢复/手动开麦推进。
- 若缺少可验证的阶段起点，明确拒绝并保留现状，不能猜测预算。重复请求不能重复退还时间。
- 当前 `runtime_snapshot` 持续覆盖，不能当作历史起点。新增入阶段同事务的持久化
  checkpoint（可复用现有JSON快照字段），冻结阶段/动作入口、有效尝试边界、双方预算和
  context/generation；不持久化无效的单调时钟绝对值。历史活动场没有该checkpoint时
  明确拒绝阶段重置，不能从音频时长或事件时间猜算。

### 重置当前发言

- 使用切片 B；RUNNING/PAUSED/ERROR/SYSTEM_RECOVERY 的具体可恢复状态显式校验。
  重置后显示将回到的阶段和发言者；不会用旧请求直接恢复播放或自动开真人麦克风。

### 跳过当前发言（AI 辅助占位）

- 管理员明确操作后先暂停并精确退役旧尝试，使用当前已配置文本模型、权威持方/阶段与
  有效历史生成简短占位正文；等待期间不能继续计时或并行执行另一次应急操作。
- 请求有时限、既有一次重试和取消边界；失败保持可恢复暂停，清晰显示“占位未生成”，
  不写空成功、不自动切模型、不用本地假文本冒充 LLM 成功。
- 成功提交必须再次校验目标 speech/阶段/operation generation/context，事务提交后推进
  恰好一次。公开历史和后续上下文标记“管理员 AI 辅助占位，未实际播报”，不冒充真人原话。
- 占位不占额外语音时长，不调用 TTS、不在大屏突然代真人开口；该回合标记已跳过。
  自由辩论只扣该尝试真实已使用且尚未结算的时间，未说的时间仍留在本方总预算，
  不退还已消耗时间、不虚扣整回合上限；固定发言跳到下一动作，未用单次额度不转移。
  例：自由方起点60秒、单次上限10秒，0秒跳过余60、已说4秒余56、到时10秒余50；
  Agent首PCM前跳过余60。LLM等待均不额外扣时。裁判可看到事故说明，但不把合成占位
  作为原辩手实绩评分依据。
- 复用事件/尝试和状态字段实现；若确需追加来源字段，只追加兼容 migration，绝不改旧 migration。
  已 FINISHED/TERMINATED 的 reset/skip 一律拒绝，不重复触发评分、归档或比赛结束。

## 6. 切片 E：主持专属音色与首尾

  同 provider_voice 的 AGENT 别名、规则 Agent 池与新房间自动填充均排除，不能仅按 kind 隔离。
- 使用正常资源接口、版本与审计调整配置，保留已有引用；历史规则/房间/比赛快照不重写。

- 开赛和恢复提示也遵守同一主持身份，不能另取全局可变音色；新规则全部主持资产成功生成

## 7. 切片 F：按阶段展示与大屏

| 权威阶段 | 中央主要信息 | 计时与操作 |
|---|---|---|
| 候场 | 辩题、双方阵容、候场说明 | 管理员开始；无发言计时和发言权 |
| 开赛/恢复倒计时 | 明确倒计时及将进入的阶段 | 只显示权威剩余值 |
| 主持播报 | 主持专属身份、环节说明 | 无辩手计时假占位 |
| 等待真人开始 | 已获权辩手与手动开始提示 | 准备状态；只有本人可开始 |
| 真人/Agent发言 | 当前辩手、持方、阶段、剩余时长 | 正常发言计时 |
| Agent生成/语音准备 | 明确正在准备及可恢复提示 | 未首PCM不显示正在发言倒计时 |
| 收尾/识别整理 | 正在整理上一段，明确交接阶段 | 停止上一段计时；合法申请独立呈现 |
| 自由辩论等待/选人 | 当前申请方、队列和双方真实余额 | 只显示本阶段有效预算 |
| 暂停/故障/系统恢复 | 原因、停在哪一步、可采取的动作 | 冻结时钟；有权者可恢复/应急 |
| FINISHED | 比赛结束、感谢、真实归档/评分状态与赛后入口 | 无等待发言者/发言权/`--:--` |
| TERMINATED | 比赛已终止、记录保留说明 | 无继续比赛/发言控制 |

- 终态优先于残留 action/free 字段；不把“记录已经归档”作为未检查实际状态的固定保证。
- 大屏模式真正单列主区域填满可用视窗，移除隐藏侧栏留下的列和1660px上限，保持双方4席可见；
  左上角复用正式稷下品牌组件。采用随宽高变化的有界字号/间距，宽屏与低高度均避免裁剪。
- 检查1280×720、1920×1080、2560×1440、3840×2160、3440×1440、1024×768及窄屏；
  控制台/历史使用内部滚动，终态与含长姓名/辩题时不挤出主要内容。
- 保留普通模式与键盘退出大屏；动画仅 transform/opacity，支持 reduced-motion。

## 实施细化：已取消订阅的音轨退役

完整模拟发现已取消订阅的 `RemoteTrack` 仍可能被消费任务及
`AudioStream` 持有，导致其原生资源等到整场关闭才退役。这属于本规格
旧 ASR 输入、异步任务与恢复资源清理的验收范围。

- ASR 接收端和模拟观众按所属 Room、参与者、publication、精确 Track
  对象登记消费任务；取消订阅、同 publication 替换及接收端关闭只退役原 owner。
- 退役先禁止旧输入，再取消旧消费任务，由原有 finally 关闭对应 AudioStream；
  重复事件、未开始的任务和迟到的旧事件不得关闭新轨道，也不得重复取消清理任务。
- 保留识别请求、connection_epoch、发言六字段、重连及收尾规则；轨道退役不自行
  推进比赛或更改语音供应商、模型、媒体协议、权限、计时和既有超时/重试预算。
- 以原 SDK 控制、同网络双观众对照及新一轮完整混合 4v4 证明资源退役和真实音频；
  不删除原失败，不放宽 PCM、裁判、回放和最终 owner/pending 清零门禁。

### 当前 Agent 回调的代次判定

独占 PostgreSQL 强控制确认，按 `created_at` 选最新生成记录可能静默丢弃当前
失败回调；普通恢复又可能在同一 context 重新从 attempt 1 开始，单按最大 attempt
也不能代表当前任务。当前 Agent 回调先通过运行时公开只读接口核验精确注册任务、
generation、完整 callback envelope、action、Agent 和退役状态，再校验数据库 Match
与生成记录的上下文及身份，最后串行进入 Actor。历史分页排序不随此调整；旧任务、
同 attempt 的旧 generation、旧 context 和已退役回调继续被拒绝。失败处理和文本完成
中同类“最新”判断均须验证正常重试、重置及同 context 恢复。
