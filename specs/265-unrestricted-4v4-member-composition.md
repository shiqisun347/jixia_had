# Spec 265：所有 4v4 赛制允许自由成员组成

版本：v2.0\
状态：已批准实施并完成生产发布（2026-10-10）\
日期：2026-10-10\
需求来源：用户要求 YXH 等所有赛制允许任意真人/Agent 组成，包括纯真人和纯 Agent\
依赖：200、213、216、261、263、264

## 1. 事实来源与冲突决议

已读 AGENTS.md、agent_docs、PRD、TechDesign 和语音 Spike。根目录 PRD 工作副本被删除，
本次从 Git HEAD 读取正文，不恢复或覆盖用户工作区。

PRD 第 1、2.3、4.2、4.3 节支持纯真人、纯 Agent 和混合 4v4，纯 Agent 专用房由管理员组织。
Spec 261 后来限制为每方 2 真人 + 2 Agent，与本次明确需求冲突。本规格批准后取代 Spec 261
的成员比例限制及“全 Agent 不可创建/启动”验收条款；大屏、事故控制台和其他安全条件继续有效。
不改变新房间只支持 4v4、历史非 4v4 只读的范围。

## 2. 代码证据

- `rooms/service.py` 的 `ensure_formal_human_agent_mix` 对每方强制 2 HUMAN + 2 AGENT，
  `start_room` 无条件调用，故 YXH 与其他规则均受影响。
- `create_room` 直接拒绝 `is_all_agent=true`，忽略原本已传入的 organizer_role；前端固定发送 false。
- 普通创建始终要求 8 个合格 Agent 并填满席位；`inspect_rule` 和 `enable_rule` 也要求 8 个 Agent，
  默认模型缺失同样会阻断纯真人使用。仅删除开赛比例校验不能解决无 Agent 的纯真人建房。
- 使用指南仍写“每方 2 真人 + 2 Agent”。既有设备、席位交换、在线准备、Agent 唯一性校验可复用。

## 3. 产品行为

### 3.1 席位与成员比例

每方固定 4 席，各席可以是真人或 Agent；两方比例独立。允许每方真人数 0–4 的全部 25 种组合，
例如全真人、全 Agent、单方全真人对单方全 Agent，以及 3+1 对 1+3。赛制不保存固定成员配额，
YXH 不做特例，不新增每套规则的“允许纯人/纯 Agent”开关。

开赛前仍须准确包含正反方各 1–4 的八个合法席位，全部填满；不允许重复用户、重复 Agent、
跨规则 Agent、缺少 occupant ID 或非法 occupant 类型。每名真人必须在线、有效设备检测、准备、
已确认适用条款；只检查实际 Agent 席位的启用状态、模型、音色和冻结配置。
未选席的辩手成员仍需选席或切观众，不允许以取消比例约束绕过这些安全条件。

### 3.2 创建与等待房间

创建提供“真人与 Agent 自由入席”“纯真人”“纯 Agent”选项。前两种允许普通房主；
纯 Agent 专用房沿用 PRD，只允许管理员组织，创建者不占席且无需麦克风检测。
普通房主可以在等待阶段转为观众；权限仍由 organizer_user_id 决定。自由入席普通房间的
最终八席也可全部是 Agent，房主以观众身份组织，沿用普通房间的在线/转交规则，不能据此
获得管理员专用房的多房间管理或离线组织权限。

自由入席沿用合格 Agent 随机补位，候选不足八个时只填可用且不重复的 Agent，其他席位显示空位，
真人可填补；不得因候选不足直接拒绝创建。纯真人初始八个空席，关闭 Agent 自动补位。
纯 Agent 专用房必须有八个合格且不重复的 Agent，否则阻止创建并说明缺额。
复用 `auto_fill_agents`，创建请求增加默认 true 的该字段；`is_all_agent=true` 要求自动补位，
纯真人发送 false。旧客户端保持自由入席默认行为。等待中的换席、离席、角色切换按此标志
恢复 Agent 或 EMPTY，不能将纯真人房偷偷补成 Agent 房。

纯真人房不要求 Agent 池、默认 Agent 模型或 Agent Prompt 可用；主持音频、有限阶段结构、
已启用的 AI 裁判等实际使用依赖仍需满足。实际选入 Agent 时必须验证该 Agent 的依赖和 Prompt。

### 3.3 赛制就绪与能力

将 Spec 264 的全局“默认模型/八个 Agent”门禁改成独立的 Agent 使用能力；基础 readiness
校验正式结构、主持资产与批准、实际启用的裁判等。Agent 池不足或默认 Agent 模型停用
不能阻止纯真人使用，也不能伪装为纯 Agent 可用。目录和创建页显示可用 Agent 数、
纯真人/自由入席/纯 Agent 能力及对应原因。启用服务、普通目录、快照加载使用同一校验，
不保留第二套无条件八 Agent 校验。

冻结快照只要求实际使用的 Agent 依赖完整；保留既有规则、房间/比赛快照、generation 与历史文件。
已创建的等待房间使用冻结配置并按新比例门禁启动；已运行比赛不改写成员或快照。

## 4. 实施切片

1. Core 先替换比例校验为合法完整席位校验，恢复纯 Agent 创建的角色检查；补参数化单测与
   独立 PostgreSQL 房间服务集成，验证全部比例、权限、设备、重复身份和并发开赛。
2. 拆开基础就绪与 Agent 能力，支持无 Agent 纯真人创建、有限补位、EMPTY 恢复和依赖冻结；
   同步 enable/catalog/snapshot 等入口，不修改旧 migration。
3. 从 OpenAPI 生成请求/响应类型，Web 增加成员方式选择、能力说明与空席状态，修正指南、
   相关测试和 Storybook。Web 不计算权威开赛条件。
4. 通过回归与构建后，零活动比赛预检、备份、受控发布、公开/授权 API 冒烟、稳定性观察，
   更新 MEMORY 与规格状态。

不更改 MatchActor 计时、自由辩论算法、回调身份信封、ASR/TTS 失败语义或实时媒体协议。
纯真人自由辩论应无 Agent 决策调用；纯 Agent 应复用既有无在线真人跳过窗口的路径。
若完整流程暴露 Actor 缺陷，记录具体证据并在本规格允许的成员兼容范围内修复，不能顺手更改算法。

## 5. 验收

- 所有正式 4v4 规则共用行为，无 YXH 名称/ID 特判；全部 25 种双方成员比例可经正常校验启动。
- 八真人、八 Agent、4 真人对 4 Agent、3+1 对 1+3 各有持久化开赛证据；至少纯真人、纯 Agent、
  混合短赛经固定发言/自由辩论完整流程模拟自然结束，不用强制终止替代完成。
- Agent 池为 0、默认 Agent 模型缺失时，基础合格的纯真人规则可启用、建房、入席、准备、开赛；
  不产生 Agent 调用。自由入席缺额可由真人填补；纯 Agent 缺额明确阻止，不能重复 Agent。
- 缺席、未准备、设备失效、未选席辩手、停用或非法 Agent、普通用户伪造管理员专用房仍被拒绝；
  五场容量、三秒开赛、权限与房间占用约束继续生效。
- 真人房离席/换席不补 Agent；自由入席不重复补位；成员锁定后不能变更；旧快照保持可读。
- Core/Jobs 对应回归、独立数据库集成、Web 单测、类型/Lint、OpenAPI、相关 Storybook/Playwright、
  仓库生产构建与 diff check 通过。未执行的物理麦克风、盲听和压力验收明确保留未验收。

## 6. 发布与回滚

不预计数据库变更；确有需要时只追加 migration 并单独验证。发布必须零非终态比赛且保存
Core/Web 制品备份，不触碰 api.md、环境文件、密钥或历史数据。

回滚恢复旧应用制品和既有校验；新增比例的 WAITING 房间仍保留，但旧版可能拒绝启动，应提示
暂停创建并重新发布兼容版本，不能改席位或删除房间解决。不得在新比例比赛运行期间回滚到
只支持 2+2 的代码；不 downgrade 数据库、不清理 generation 或音频。
