# v2.1 实验管理工作区重设计

> 状态：已完成  
> 日期：2026-08-22  
> 依据：用户要求实验管理简洁、对管理员友好，并完整支持创建、修改和删除

## 1. 目标

把单个超长实验配置页面改为可扫描、可恢复的管理工作区。管理员应始终看清：有哪些批次、
当前批次处于什么状态、下一步做什么、哪些操作不可逆。

## 2. 信息架构

- 左侧批次栏：搜索、状态筛选、批次状态、创建入口；不再用单个下拉框隐藏全部批次。
- 右侧工作区：当前批次摘要、明确的生命周期操作和与状态匹配的内容。
- DRAFT 使用三步流程：`基本信息`、`人员与 Agent`、`辩题与排表`。每步显示完成状态，
  管理员可来回修改；发布动作只位于最后一步。
- PUBLISHED/DISABLED 不再展示可编辑表单，直接展示比赛进度、结果门禁、导出和保留期操作。
- 批次提供“实验设置”入口，集中查看固定 Agent、模型、Prompt 版本和实际 Prompt 模板；
  每个已有 match 的场次直接进入管理员比赛工作台，查看完整请求输入、原始输出和事件日志。
- 已发布批次的场次进度直接显示中文轮次、辩题、正反方队伍、比赛/尝试状态、标注完成度
  和结果状态；管理员不需要再对照机器编号或排期文件才能定位比赛。
- 无批次、加载失败、无选择、无搜索结果均提供明确空态和下一步操作。
- 用户端“实验安排”入口始终可见；创建房间页将 `formal-4v4-standard` 标记为论文同款赛制。
  普通用户使用该规则时仍创建普通公开房间，自行邀请真人或使用 Agent，不套用固定排表。

## 3. 生命周期操作

- 创建：弹窗只包含批次编号、名称和已完成音频审核的 4v4 赛制；字段就地校验。
- 匿名账号：P01-P18、E01-E03 使用统一默认密码且不强制首次改密；准备动作可重复执行，
  页面只显示统一账号范围、默认密码和处理数量，不展示 21 行一次性凭据。
- 导出：机器 CSV 继续用于排表往返；另提供中文列名的“清晰排期 CSV”和包含 P01-P18、
  E01-E03 用户名、用途、统一密码的“账号 CSV”，两者均使用 UTF-8 BOM 便于 Excel 打开。
- 修改：仅 DRAFT 可修改编号、名称和赛制；服务端事务内再次校验状态、编号唯一性和赛制。
- 删除：仅 DRAFT 且不存在任何 attempt 时允许；确认框明确列出将删除的草稿阵容与排表。
  删除操作按外键依赖顺序清理草稿数据，不删除账号、Agent、辩题、规则或审计。
- 发布：保持服务端完整校验；确认框说明发布后阵容和排表冻结。
- 停用：仅 PUBLISHED 可用；与删除分开呈现，确认框说明历史数据保留。DISABLED 无操作按钮。

## 4. 交互细节

- 切换批次时重置本地草稿，避免把上一批次配置误保存到下一批次。
- 服务端数据用 TanStack Query 管理；表单只保存未提交值，不复制进度状态。
- mutation 期间禁用重复提交，成功后刷新批次、排表和进度缓存，并保留合理选择。
- 危险操作使用现有 `ConfirmDialog`；删除与停用使用不同文字，不使用浏览器原生 dialog。
- 主要控制在 390px、1280px、1440px 和 1920px 不溢出；批次栏在窄屏堆叠到工作区上方。
- 页面不使用教学文案解释功能；状态和按钮名称直接表达当前可执行动作。

## 5. API 与数据边界

- 新增 `PATCH /api/admin/experiments/batches/{id}`，请求为 `code/title/rule_id`。
- 新增 `DELETE /api/admin/experiments/batches/{id}`，成功返回 204。
- 两个 mutation 均要求管理员、浏览器 Origin 校验和实验创建开关开启。
- 不新增 migration；不修改已发布 migration。
- 审计记录批次修改和草稿删除，不记录敏感信息。

## 6. 验收

- 管理员可在 UI 完成创建、修改、草稿删除、发布和已发布停用。
- 已发布/停用批次无法通过 API 修改或删除；有 attempt 的草稿删除失败。
- 删除草稿后批次列表与选择立即更新，不留下空白或指向已删除 ID。
- 浏览器覆盖空态、创建、修改、删除确认、三步配置、发布确认与停用确认。
- Core、Web、contracts、Storybook、Playwright 和生产构建通过。

## 7. 回滚

- Web 可回滚到旧管理页，新增 API 保持向后兼容。
- Core 回滚不会影响已有批次；删除只作用于管理员明确确认的无 attempt 草稿，无法自动恢复。
