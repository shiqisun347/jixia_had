# v2.0 备份与恢复边界

公开初始化和生产完整灾备是两个工件。本文描述所需步骤与验收；实际备份位置、校验和、恢复结果由当次私有回执保存，不在公开文档写入凭据、用户信息或备份内容。Spec328 整理本身不重启服务、不暂停或终止比赛。

## 保留什么

| 工件                 | 内容                                                                   | 保存范围                      |
| -------------------- | ---------------------------------------------------------------------- | ----------------------------- |
| Git 稳定提交         | 已发布源码、49迁移、锁、测试、脱敏部署模板、公开资源与资产清单         | 公开仓库                      |
| 工作区/Git 历史归档  | 未发布候选、个人参考、完整历史与不可替代失败证据                       | 仓库外私有归档，先备份后整理  |
| 完整 PostgreSQL 备份 | 全部734模板、资源、账号、历史比赛、发言及相关表                        | 加密私有灾备，不进Git         |
| 持久文件             | 主持音频、上传头像、Agent/比赛录音、导出与数据库引用的其他文件         | 私有灾备；逐路径/SHA/大小清单 |
| 同构建运行包         | 当前Core/Jobs、Web完整standalone/static/public、依赖/构建标识          | 私有回滚包与脱敏manifest      |
| 运行与认证材料       | 原生unit/依赖、代理、LiveKit、EnvironmentFile、模型加密主密钥和TLS材料 | 敏感部分单独加密托管          |
| 独立Showcase         | SQLite一致性备份、站点源/素材、私有运行配置                            | 与辩论数据分开保存            |

SQL备份不能替代录音/头像文件，也不能替代加密主密钥。仅有模型密文而没有对应主密钥不能完成恢复。不要把生产dump、完整只读快照或整个 `profile_output` 强制提交到Git。

## 在线备份

1. 先记录精确源/锁/迁移/构建/配置哈希与服务状态，核清活动比赛、房间、连接和后台任务。比赛正在运行时不结束它们来获得备份窗口。
2. 使用PostgreSQL一致性custom dump流向受保护的异机存储，连接由私有环境提供；不在服务器生成耗尽磁盘的大型临时副本，不把连接串放进参数或日志。
3. 对数据库引用的持久文件逐项备份和验签，按实际路径/realpath识别仓库外数据目录。数据库快照与可变文件不是天然同一事务；缺文件、大小变化或后台清理竞争时不能宣布完整，应在自然空窗补齐并重新核对引用。
4. SQLite使用其一致性backup机制，不能在WAL写入期间只复制主文件。Showcase认证材料和投票历史不进入公开源码。
5. 保存归档可读性、完整文件SHA、数据库目录/表计数与恢复入口。确认异机副本完整并完成隔离恢复前，不因“已有压缩包”就删除历史文件或失败证据。

环境文件和密钥若纳入授权私有备份，只能作为受保护的密封数据保存，不读取到终端、文档或普通日志。执行过程中不改变模型/供应商、服务或生产数据，不把备份脚本变成自动清理器。

## 隔离恢复

- 使用新建、自有、回环地址的实例/数据库及独立端口。先核归属、目标名称和无现存数据；不在生产目录或既有QA库验证恢复。
- PostgreSQL按备份兼容版本恢复，不运行破坏性downgrade、不重写已发布迁移。核唯一head、资源/历史计数及引用文件清单，保留旧数据原文。
- 恢复认证材料和正确加密主密钥只用于授权私有副本。测试前阻断真实出网，核后台队列，避免恢复出的任务直接调用供应商；公开资源初始化使用新管理员和新注入密钥，见[复现文档](v2-reproduction.md)。
- 标准数据库/认证测试含TRUNCATE，必须再使用另一套新可销毁测试库，不能对恢复出的完整历史副本运行。
- Web恢复同构建整包，不能混用static/public/standalone；Core和Jobs实际导入路径及LiveKit SDK需与manifest一致。部署和服务依赖见[部署文档](deployment.md)。
- 独立Showcase恢复只处理它自己的数据/站点；不以旧SQLite覆盖恢复后新产生的投票。代码回滚和数据时间点恢复分别授权、分别记录。

恢复验收应保留来源归档SHA、目标归属、迁移、资源/历史/文件哈希、健康与权限、新房冻结和清理回执。未实际执行的完整混合赛、RTC、现场声音或压力测试继续标待验收。

## 回滚

本地整理可从私有工作区归档和Git bundle恢复；不删分支、不改写历史、不force-push。已发布迁移不回退。

普通配置逆向必须新增正常修订和审计，在新鲜活动/历史门禁下核对；新房/历史变化后不能强行套用旧backup。生产应用回滚使用同构建旧包及兼容数据库，Core停止可能连带停止依赖它的Web，恢复必须覆盖实际依赖。未知提交、外来漂移或新活动不得盲重试或擅自结束比赛。
