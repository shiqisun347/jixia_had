# 稷下 v2.1 线上实验操作手册

> 适用版本：v2.1 / 2.1.0  
> 线上地址：<https://debate.vsagents.online/>  
> 当前状态：应用和正式实验能力已上线；`SIM_20260822_V21` 仍为 DRAFT 模拟批次，不是正式招募批次。

## 一、当前可用入口

- 首页：<https://debate.vsagents.online/>
- 比赛大厅：<https://debate.vsagents.online/lobby>
- 实验安排：<https://debate.vsagents.online/experiments>
- 排行榜：<https://debate.vsagents.online/leaderboard>
- 管理员实验管理：<https://debate.vsagents.online/admin/experiments>
- 登录后直接回到实验安排：<https://debate.vsagents.online/login?return_to=%2Fexperiments>

实验安排和管理页面都要求登录。未列入已发布排表的普通用户不能成为实验辩手，只能按公开比赛规则观战。

## 二、正式开赛前必须满足

只有以下事项全部完成，管理员才可以启用正式实验：

1. 研究负责人完成 P01-P18、E01-E03 与真实身份/联系方式的受控对照。
2. 确认 P01-P18、E01-E03 账号可使用统一默认密码登录。
3. 完成真人麦克风、设备恢复、持续五场长链路和真人音色盲听验收。
4. 确认 C1-C7、六个固定 Agent、6 队 roster 和 18+3 排表无误。

正式实验能力已开放，但上述现场检查仍是发布正式招募批次和开赛的前置条件。

## 三、管理员配置正式批次

### 1. 登录和检查

登录管理员账号，打开“管理员实验管理”。先确认：

- 规则为已完成音频审核的 4v4 规则；
- C1-C6 为正式题，C7 为独立训练题；
- 六个 Agent 使用同一模型、不同音色；Agent 可担任包括一辩在内的任意席位；
- 服务器没有 `RUNNING`、`PAUSED` 或未终止的比赛。

### 2. 创建和选择批次

点击“新建批次”，只填写批次编号、名称和 4v4 实验赛制，再点击“创建草稿”。左侧批次栏可以搜索并按草稿、已发布、已停用筛选。选中草稿后可随时：

- 点击“编辑基本信息”修改编号、名称和赛制；
- 点击“删除草稿”删除没有比赛记录的草稿；
- 点击“清晰排期表”导出中文可读排期；
- 点击“账号与密码”导出全部实验账号；
- 点击“Agent 与 Prompt”查看本批次 Agent 映射和当前实际 Prompt。

已有比赛记录的草稿不能删除。已发布或已停用批次不能再修改。

### 3. 准备账号和固定阵容

在“人员与 Agent”中点击“准备账号”。系统会创建或复用 P01-P18、E01-E03，并统一设置默认密码 `Jixia2026`，不要求首次登录改密。按钮可以重复点击，用于恢复统一密码。

需要交付账号时，点击批次工具栏的“账号与密码”，获得包含编号、用户名、默认密码、用途和状态的 CSV。

按以下关系绑定：

| 队伍 | 参与者 | Agent |
| --- | --- | --- |
| T01 | P01-P03 | 乾元 |
| T02 | P04-P06 | 坤元 |
| T03 | P07-P09 | 慎思 |
| T04 | P10-P12 | 破阵 |
| T05 | P13-P15 | 见微 |
| T06 | P16-P18 | 观澜 |

专家固定为 E01、E02、E03。点击“保存并继续”后进入排表步骤。页面会阻止参与者、专家或 Agent 重复使用。

### 4. 生成排表

选择 C1-C6 作为正式题，选择 C7 作为训练题，点击生成排表。系统应显示：

- 18 场正式赛；
- 3 场训练赛；
- 每人参加 6 场正式赛；
- 每人担任 2 次一辩；
- Agent 只出现在二、三、四辩；
- 每队正反方各 3 场。

“导出机器 CSV”用于系统往返导入；批次工具栏的“清晰排期表”使用中文列名和可读账号/Agent 名称，适合管理员检查和线下排班。排表有 attempt 后不能再修改。

### 5. 发布

确认阵容、题目和排表后点击“发布排表”。发布后阵容和排表冻结，参与者才会看到预约。

发布前如果任一外部服务或真人设备验收失败，保持 DRAFT，不要绕过校验。

### 6. 查看设置、日志和原始调用

- “Agent 与 Prompt”展示六支队伍的固定 Agent、Prompt 版本、决策 Prompt 和发言 Prompt；“打开 Agent 管理”进入完整 Agent 设置。
- “打开系统日志”进入平台日志页。
- 已创建比赛的场次会显示“数据与请求日志”，进入该场比赛工作台后可查看转写、事件、外部调用，以及每次调用的完整请求输入和原始响应。
- 已发布批次的“研究数据与保留期”可生成匿名研究包和执行只读保留期检查。

## 四、参与者操作

1. 打开“实验安排”，使用管理员分配的 P 编号和统一默认密码登录。
2. 在“我的实验安排”查看预约时间和场次；不能在房间内自行选择席位。
3. 进入预约后只做设备检查，确认麦克风、扬声器和网络；席位由排表自动分配。
4. 比赛中按主持人和系统状态操作。自由辩论阶段可以举手或取消举手；Agent 的状态仅对本队授权用户显示。
5. 比赛结束后完成事件标注和整场问卷。未完成前，个人评分结果保持不可见；完成后可以查看本人可见的比赛结果。
6. 账号异常、设备故障或需要暂停时，联系本场一辩或管理员，不要新建替代账号。

## 五、专家操作

专家使用 E01-E03 登录同一“实验安排”入口。进入“专家标注”后：


1. 只处理系统分配的冻结机会；
2. 按页面要求独立完成标注；
3. 提交后不能修改；
4. 不查看其他专家答案，也不应获得未来比赛内容。

## 六、比赛控制规则

- 每方席位号最小的真人和管理员可以开始、暂停、恢复、重置当前发言和终止比赛；Agent 坐一辩时，
  控制权自动顺延给本方下一位真人。
- 普通参与者只能在授权范围内控制自己的发言或执行自身暂停恢复。
- 进行中或暂停的比赛必须先终止，才能重新开赛；已正常完成的排表场次不能重复开赛。
- 等待人类举手期间不消耗本方自由辩论时间；等待超时会进入暂停/恢复流程。
- 暂停后恢复会重新开始完整 60 秒纯人类等待，Agent 保持本轮“跳过”。
- 迟到的 Agent 决策或 ASR final 只写入实验数据，不改变已经确定的本轮发言者。

## 七、实验结束和停用

管理员在“管理员实验管理”中确认没有活动 attempt 后，执行“停用批次”。停用后：

- 不能创建或进入新的实验比赛；
- 历史比赛、标注、问卷、评分和导出保持只读；
- 普通三阶段比赛和普通排行榜继续可用；
- 不删除数据库数据，不回滚 migration。

## 八、服务器发布检查

以下命令只读检查服务、版本、健康接口、migration 和非终态比赛，不会自动修复服务器：

```bash
cd /opt/jixia-debate
JX_PREFLIGHT_UV=/root/.local/bin/uv bash scripts/ops/preflight_v2_1.sh
```

发布源码或 standalone 后，必须重启受影响的 systemd 服务，再重复 preflight。生产 provider 探针不写业务数据：

```bash
set -a; . /opt/jixia-debate/.env; set +a
PYTHONPATH=/opt/jixia-debate/apps/core/src:/opt/jixia-debate/apps/jobs/src \
  /root/.local/bin/uv run --frozen --no-sync --package jx-core \
  python scripts/ops/provider_chain_probe.py --load
```

探针输出只看成功数和延迟，不保存 Prompt、模型正文、音频或密钥。任何失败都保持实验开关关闭。

## 九、安全提醒

- 不把 `api.md`、`.env`、私钥、密码或临时凭据提交 Git。
- 账号真实身份对照表与平台匿名数据分开保存。
- 当前对话和 `api.md` 中曾出现服务器凭据；在正式招募前必须轮换 root 密码、吊销旧私钥并重新执行 preflight。
