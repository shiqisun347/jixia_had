# v2.0 结构审计

日期：2026-08-21

## 结论

v2.0 将新建比赛收敛为正式 4v4，但不通过删除历史兼容代码制造迁移风险。
本轮整理删除的是重复版本字面量和互相冲突的当前状态说明，不删除仍被 4v4、
恢复或历史读取使用的代码。

## 已收敛

- Python 根包、Core、Jobs、Web、Contracts 和 FastAPI 统一报告 `2.0.0`；
  FastAPI 从 Core 包版本读取，不再维护第二个版本字面量。
- 创建页只列出 4v4 规则且无规则时阻止提交；Core 在创建事务内拒绝
  `side_size != 4`，旧客户端不能绕过。
- PRD、TechDesign、README、开发契约、AI 入口、部署说明和 `agent_docs`
  统一描述 v2.0/4v4 边界。
- `MEMORY.md` 从逐次过程日志收敛为当前版本、已发布基线、最新证据和遗留风险；
  详细历史留在规格与研究材料中。

## 明确保留

- 已发布 migrations 和数据库中 1v1 至 5v5 的约束：历史数据不得改写。
- 通用规则 parser/compiler 与 MatchActor：4v4 多阶段、自由辩论和恢复仍使用。
- 非 4v4 snapshot reader、管理端历史展示和回归 fixture：用于审计旧比赛。
- 规格 161–170 与 `docs/v1.0-audit.md`：属于 v1.0 回归/发布证据。
- `paper_docs/`、`api.md`、`.env` 和生产数据：用户材料或敏感文件，不纳入整理。

## 删除门槛

未来删除兼容代码前，必须先证明生产无引用数据、提供前向 migration、覆盖历史
snapshot 读取/恢复，并在独立规格中批准回滚边界。仅凭“v2.0 只做 4v4”不足以
删除这些路径。
